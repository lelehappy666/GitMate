# 传统提交可调分栏与全分支状态实施报告

## 完成范围

本轮完成传统提交布局的结构性调整：

1. 中间竖向分割线支持鼠标拖动，左侧分支图和右侧提交信息实时调整宽度。
2. 分割线宽度写入仓库独立场景，重新打开同一仓库后恢复；拖动过程只更新界面本地状态，鼠标松开时才保存最终值。
3. 双击分割线恢复默认宽度。
4. 本地分支与同名远程跟踪分支合并为一条逻辑泳道，`origin` 优先作为主要远程身份，全部引用标签保留。
5. `main` 存在时固定为第零泳道；只有 `origin/main` 时仍优先主分支；没有任何 `main` 时回退当前 HEAD。
6. 所有本地、远程、仅远程、detached 和 synthetic 分支均进入投影，不再用“其他分支”聚合槽隐藏真实分支。
7. 同名 synthetic 分支按真实 ID 保持独立，不会因通用展示名称错误合并。
8. 左侧泳道使用固定间距，分支较多时只在左侧区域横向滚动；右侧头像、标题、作者、哈希、日期和标签保持固定。
9. 从任意远程跟踪引用可达的提交和父边使用实线；只从本地分支可达的已提交但未推送记录使用同色虚线，并显示“未推送”徽标。
10. 工作区尚未 commit 的文件继续显示在独立“工作区未提交”摘要，不生成伪提交节点。

## 核心实现

### 全量逻辑分支

`CommitGraphTraditionalBranchProjector` 不再根据窗口宽度限制 4–8 条分支，而是按名称建立完整逻辑分支：

- 本地 `main` 与 `origin/main` 共用一条泳道；
- 本地 `<name>` 与 `origin/<name>`、其他远程同名分支共用一条泳道；
- 仅本地与仅远程分支分别保留；
- detached 与 synthetic 使用真实 ID，禁止错误合并；
- 每条逻辑泳道保存全部底层分支 ID 和标签，搜索仍覆盖全部真实引用。

### 发布状态索引

新增 `CommitGraphTraditionalPublicationIndex`。完整快照派生时分别从所有本地和远程 tip 沿父边遍历，构建两个不可变集合。Canvas 绘制节点和连线时只做 O(1) 查询，不在每帧重复扫描历史。

### 分栏与持久化

场景 schema 从 4 升级到 5，新增 `traditionalDividerWidth`。旧场景迁移后保持 `nil`，界面按默认公式计算；场景对账和布局迁移完整保留该字段，未来 schema 只读保护不变。

新增 `CommitGraphTraditionalSplitLayout` 统一处理默认宽度、左右最小宽度、超窄窗口、非有限输入、泳道偏移和可见泳道范围。

### 传统界面

新增 AppKit 分割线手柄，提供 10 点命中区和左右调整光标。上一版错误的整层横向拖动已经移除：触控板横向滚动只在左侧分支区生效，右侧信息不参与平移。

头像层继续只创建真实可见行，并随分割线统一调整固定起点，不会穿透固定头部或发生越界。

## 测试覆盖
