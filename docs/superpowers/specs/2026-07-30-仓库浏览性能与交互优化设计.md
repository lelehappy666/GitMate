# 仓库浏览性能与交互优化设计

## 1. 目标

本轮优化页面 10–15 中四个高频使用区域：

1. 将提交历史和提交图改为最早提交在上、最新提交在下，并同时包含全部本地分支和远程分支。
2. 将提交图改为高性能矢量画布，解决鼠标拖动卡顿，并支持画布内滚轮围绕鼠标位置缩放。
3. 修正文件树展开后的层级顺序，使子目录和子文件始终紧跟父目录。
4. 让仓库总览与 README 复用缓存和进行中的请求，降低重复切换页面时的等待时间。
5. 用“仓库卡片 + 可搜索浮层”替换侧边栏原生菜单式仓库切换器。

本轮不改变 Git 仓库内容，不自动执行提交、推送、拉取、重置或其他写操作。

## 2. 总体方案

采用单一矢量 `Canvas` 绘制提交图，使用一个轻量 AppKit 交互层统一接收鼠标拖动、滚轮、触控板缩放和节点点击。画布只绘制当前视口及其缓冲区内的节点和连线，交互增量按显示帧合并，避免每个鼠标事件触发整棵 SwiftUI 节点树重排。

文件树排序从“全局按路径深度排序”改为“父子邻接表 + 前序遍历”。仓库内容加载增加共享内存缓存、进行中请求合并和缓存优先的增量结果流。侧边栏仓库切换器改成自定义卡片与搜索浮层，并继续复用现有路由模型。

## 3. 提交读取与顺序

### 3.1 引用范围

提交列表和提交图均读取：

- `refs/heads/*` 下的全部本地分支；
- `refs/remotes/*` 下的全部远程分支。

不把标签、stash 或其他任意引用当作独立分支入口。多个分支包含的同一提交按完整哈希去重，提交节点只出现一次，节点上可同时显示多个分支装饰。

### 3.2 排列顺序

Git 输出使用拓扑顺序，最终在应用中转换为父提交优先：

- 最早的根提交位于画布顶部；
- 后续提交沿纵向向下排列；
- 最新提交位于底部；
- 父提交始终出现在子提交上方；
- 合并提交保留全部父边。

由于 Git 的 `--max-count` 会在反转顺序之前截取数据，分页不能直接组合 `--reverse` 与 `-n`。实现先取得全部分支的提交总数，再把“从最早开始的页偏移量”换算成 Git 新到旧遍历中的 `--skip` 和 `-n`，读取后在内存中反转当前页。这样首屏确实从初始提交开始，大型仓库仍保持分页加载。

### 3.3 分支泳道

布局算法按父提交优先顺序处理节点：

- 根提交优先进入主泳道；
- 普通子提交默认继承第一父提交的泳道；
- 同一父提交分叉出的后续子提交分配到相邻空闲泳道；
- 合并提交优先回到第一父提交泳道；
- 已经显示过的节点在加载后续页面时冻结泳道，避免画布跳动；
- 多个不相关根提交按提交时间和哈希稳定排序后分配独立泳道。

## 4. 矢量提交画布

### 4.1 绘制

网格、贝塞尔连接线、节点圆角矩形、分支标记、系统图标和文字全部在一个 SwiftUI `Canvas` 中绘制。不使用位图快照、`drawingGroup()` 或缩放后的缓存截图，因此放大和缩小时边缘与文字保持清晰。

节点视觉层级：

- 提交主题为主要信息；
- 作者、短哈希和分支标签为次要信息；
- 当前选中节点使用蓝色加粗描边；
- 普通父边使用实线，合并边使用虚线；
- 分支颜色保持稳定，不随重新加载改变。

### 4.2 可见区域裁剪

绘制前把屏幕视口反算为画布坐标，只保留视口四周额外 180 点缓冲范围内的节点。连线只在任一端点进入缓冲范围时绘制。缩略图继续显示全局关系，但不参与主画布的高频布局。

### 4.3 交互

AppKit 交互层覆盖画布并提供：

- 鼠标按住空白区域拖动：平移画布；
- 鼠标滚轮位于画布内：围绕鼠标位置缩放；
- 向上滚动放大，向下滚动缩小；
- 缩放范围保持 `35%–200%`；
- 触控板捏合继续围绕指针位置缩放；
- 单击节点：打开现有提交详情弹层；
- 双击空白区域：恢复适配全部节点；
- 鼠标移出画布后，滚轮恢复页面或系统默认行为。

拖动和滚轮增量在一次显示刷新中合并为一次视口更新，避免高频事件重复触发绘制。

## 5. 文件树层级

文件树以完整路径构建父子邻接表，并使用前序遍历生成显示顺序：

1. 先显示父目录；
2. 展开后立即显示它的直接子目录和子文件；
3. 同一父目录下，目录排在文件之前；
4. 同类条目按本地化名称排序；
5. 子目录继续递归排列，直到未展开的目录为止。

折叠目录时只隐藏后代，不删除已加载数据；再次展开无需重复执行 Git 命令。搜索状态下显示匹配项及其祖先路径，确保用户知道匹配文件所在层级。缩进只由路径层级计算，不再参与全局排序。

## 6. 总览与 README 加速

### 6.1 共享内容协调器

`WorkspaceContentService` 内增加按“账户编号 + 仓库编号”区分的共享内容协调器：

- 完整仓库内容在内存中缓存 5 分钟；
- 同一仓库同时发起的总览和 README 请求合并为一个进行中任务；
- 新页面若命中有效内存缓存，立即取得结果；
- 访问令牌不进入缓存键、缓存值或磁盘文件。

### 6.2 缓存优先增量加载

仓库内容加载改为增量结果流：

1. 先读取有效磁盘摘要、缓存的本地记录和内存 README；
2. 有可用内容时立即显示，不等待网络；
3. 缓存过期后在后台并发刷新本地状态、最近提交、GitHub 摘要和 README；
4. 新结果到达后原位更新页面，不把页面重新切回全屏加载状态；
5. 刷新失败时保留旧内容，只显示非阻塞错误提示。

磁盘摘要继续使用现有 15 分钟有效期。README 文本只保存到进程内存，不新增私有 README 的持久化副本。

### 6.3 冷启动并发

首次没有可用缓存时：

- 本地状态和最近提交并发读取；
- GitHub 摘要和 README 并发请求；
- 仓库大小优先复用有效本地记录，后台刷新时才重新统计；
- 总览与 README 共享刷新任务，避免两页连续访问产生两套 Git 和 GitHub 请求。

## 7. 仓库切换器

侧边栏“当前仓库”区域改为自定义卡片：

- 第一行显示仓库短名称；
- 第二行显示所有者、主要语言或“未知语言”；
- 私有仓库显示锁定图标；
- 右侧使用轻量上下切换图标；
- 当前卡片保持白底、细边框和清晰悬停状态。

点击卡片打开宽约 320 点的浮层：

- 顶部是仓库名称与所有者搜索框；
- 列表显示仓库名、所有者、主要语言和当前选中标记；
- 最多显示约 8 行，超出后在浮层内部滚动；
- 搜索无结果时显示明确空状态；
- `Esc` 关闭浮层；
- 选择仓库后关闭浮层，并保持当前子页面类型。

例如用户位于仓库 A 的 README，切换到仓库 B 后直接进入仓库 B 的 README；位于总览、文件与提交、提交图时规则相同。全局工作台和全部仓库页面不因切换动作自动跳转。

## 8. 错误与边界处理

- 仓库没有任何本地或远程分支提交时，提交图显示空状态。
- 某个远程跟踪分支损坏时，Git 命令失败并显示可重试提示，不生成不完整的错误拓扑。
- 缓存刷新失败时保留最近一次可用内容。
- 仓库在浮层打开期间被移除时，选择操作回退到全部仓库页。
- 文件树出现孤立条目时，将其作为根级条目显示，避免内容永久不可见。
- 所有路径继续经过现有安全路径校验，所有 Git 操作保持只读。

## 9. 可访问性

- 仓库卡片和搜索结果提供完整仓库名称与选中状态。
- 提交画布提供整体操作提示，并为可见提交节点提供可访问性描述。
- 放大、缩小、适配画布和自动布局按钮保留键盘访问。
- 文件树继续声明目录展开状态和文件类型。

## 10. 验证策略

自动化验证覆盖：

- 全部分支 Git 参数、提交去重和最早优先分页换算；
- 多根提交、分叉、合并和分页追加后的稳定泳道；
- 视口缩放锚点、滚轮方向、缩放边界和可见区域裁剪；
- 文件树父子前序排列、折叠、重新展开和搜索祖先上下文；
- 内容缓存命中、5 分钟过期、并发请求合并、缓存优先发布和失败保留旧内容；
- 仓库切换后保持总览、README、文件与提交或提交图路由。

界面验证覆盖：

- 默认 1180 × 760 窗口下拖动画布保持流畅；
- 放大后文字、节点和连接线无明显像素化；
- 鼠标在画布内滚轮缩放，在画布外不拦截滚动；
- 多层目录展开后子项紧跟父目录；
- 总览和 README 之间往返切换能立即显示已有内容；
- 仓库浮层在侧边栏空间内清晰可读且不会遮挡主导航。

## 11. 验收标准

- 提交历史最早提交在顶部、最新提交在底部，并包含全部本地与远程分支。
- 200 个提交节点的画布在普通鼠标拖动和滚轮缩放时无持续卡顿。
- 画布缩放不使用位图快照。
- 文件树展开后的父子位置正确。
- 同一仓库总览与 README 的重复访问不再重复发起完整加载。
- 仓库切换器不再显示原生菜单式样，支持搜索并保持当前子页面。
- 新增和既有自动化验证通过，Release 构建与 macOS 应用签名成功。
