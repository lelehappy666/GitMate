# 大量提交画布与多分支传统布局设计

## 1. 目标

重新设计提交图的两种观看模式，使 GitMate 在五万条提交、数百个本地与远程分支的仓库中仍然清晰、稳定、流畅。

本次设计解决以下问题：

- 画布在提交很多时卡片密集，适配全部后无法阅读。
- 主干、分支和 Merge 关系缺少稳定的视觉层级。
- 传统布局分支过多时无限变宽、泳道拥挤或连线穿过节点。
- 用户难以在完整拓扑、当前任务上下文和具体提交内容之间切换。

## 2. 不变约束

- 提交图包含全部本地分支和远程分支可达的提交。
- 画布保持最早提交在上、最新提交在下。
- 传统布局保持最新提交在上、最早提交在下。
- 画布与传统布局共享同一份 Git 拓扑，不各自重算提交关系。
- 自动聚合只改变显示投影，不修改 Git 数据，也不创建用户 Group。
- 用户 Group、折叠状态、版本区域、固定端口、线型和手动位置保持独立。
- 项目工作区变更作为独立本地状态显示，不伪装成 Git 提交。

## 3. 画布布局：自适应主干与分支束

### 3.1 空间结构

- 默认分支第一父链构成居中的垂直主干。
- 其他分支根据稳定分支身份分配到主干左右两侧。
- 同一分支在其生命周期内保持同一侧和稳定横向位置。
- 左右分配同时考虑分支持续行范围，避免生命周期重叠的分支占用同一视觉轨道。
- 分叉边在分叉节点附近离开主干，Merge 边在 Merge 节点附近汇回，不生成穿越整段历史的长斜线。

### 3.2 三级语义显示

画布沿用现有缩放阈值，并根据缩放使用三个显示层级：

1. 完整层级（缩放比例大于或等于 0.8）：显示完整提交卡片、作者、短哈希、分支与签名状态。
2. 紧凑层级（缩放比例大于或等于 0.5 且小于 0.8）：显示紧凑节点、标题、分支颜色和关键标识。
3. 概览层级（缩放比例小于 0.5）：连续普通提交合并为分支束，只显示分支名称、提交数量和时间范围。

层级切换只改变显示模型和绘制内容，不改变节点坐标、端口或拓扑。

### 3.3 分支束生成规则

分支束是同一稳定分支上的最大连续普通提交段。以下节点必须作为独立锚点保留，不能进入分支束：

- 分叉点；
- Merge 提交及其直接父提交；
- `HEAD`；
- 本地分支顶点和远程分支顶点；
- Tag；
- 当前选中提交；
- 搜索命中提交；
- 用户 Group 的成员边界；
- 位于版本区域内的提交，以及跨越版本区域边界的边两端提交；
- 浅克隆边界提交。

分支束包含稳定 ID、分支身份、提交哈希集合、首尾提交、提交数量、时间范围、起止端口和展开状态。稳定 ID 由分支身份与首尾提交哈希生成，刷新后相同提交段继续复用。

### 3.4 画布交互

- 点击分支束后在原位置临时展开该段提交。
- 再次点击、关闭上下文或切换仓库后恢复自动聚合。
- 搜索命中分支束内部提交时自动展开、选中并聚焦该提交。
- 选中提交后，其直接父提交、子提交和相关分支束强化显示，其余内容降低对比度。
- 当全历史适配所需缩放比例低于 0.5 时，初次进入聚焦最新八十条提交覆盖的历史窗口，不执行不可读的全历史适配。
- “适配全部”在历史过长时进入概览层级，并保持最新提交处于可见区域。
- 右侧历史导航始终映射完整历史，支持跳转到最早、最新、HEAD、Tag、Group 和版本区域。

### 3.5 用户场景兼容

- 场景使用 `manuallyPositionedHashes` 明确记录用户拖动过的普通节点；自动布局只重排不在该集合中的节点。
- 用户移动过的节点和 Group 不被后台缩放或刷新重排。
- 分支束不得跨越 Group 边界。
- Group 折叠后仍按既有跨组聚合键生成连线。
- 分支束展开状态属于临时界面状态，不写入场景文件。
- 用户固定分支、传统布局可见分支偏好写入场景文件。

## 4. 传统布局：自适应上下文泳道

### 4.1 页面结构

传统布局分成固定图轨和提交信息列表：

- 左侧图轨只绘制拓扑、节点、分支标签和聚合入口。
- 右侧列表显示提交标题、作者、时间、短哈希、签名状态、Tag 和来源。
- 两侧共享纵向行高与滚动位置。
- 工作区未提交变更固定在提交历史上方，分别显示暂存、修改、未跟踪和冲突数量。

### 4.2 自动可见泳道数量

视口根据可用宽度自动选择四到八条泳道：

- 窄窗口至少显示四条；
- 中等窗口逐级增加到五、六、七条；
- 宽窗口最多显示八条；
- 每条泳道保持固定最小间距，不通过无限压缩来容纳更多分支；
- 图轨始终为右侧提交信息保留最低可读宽度。

具体阈值由纯函数根据视口宽度、节点直径、标签安全宽度和提交信息最低宽度计算，不在 SwiftUI 视图中散落魔法数字。

### 4.3 分支可见优先级

可见分支按以下顺序选择：

1. 当前 `HEAD` 默认分支；
2. 当前选中或搜索命中的分支；
3. 用户固定的分支；
4. 与当前提交存在直接分叉或 Merge 关系的分支；
5. 最近活跃的本地分支；
6. 最近活跃的远程分支。

超出可见数量的分支按“本地分支束”和“远程分支束”聚合。已合并或长期不活跃分支可以进入低优先级分支束，但不会从数据索引中删除。

### 4.4 分支切换与管理

- 图轨顶部显示“当前可见数量 / 全部分支数量”。
- 点击本地或远程分支束打开可搜索分支浮层。
- 浮层支持按名称、来源、是否已合并和最近活跃时间筛选。
- 选择一个隐藏分支后，保留 HEAD 和用户固定分支，并替换当前最低优先级临时泳道。
- 切换可见分支不改变纵向滚动位置和当前选中提交。
- 用户可以固定或取消固定分支。
- 已固定分支超过可见容量时，按最近使用时间显示，其余固定分支仍保留在浮层的“已固定”分组中。

### 4.5 传统连线路由

- 同泳道父边使用垂直直线。
- 普通跨泳道父边先沿源泳道垂直延伸，在父提交附近短距离弯曲汇入。
- Merge 边在 Merge 提交附近短距离分叉，随后沿目标泳道垂直延伸。
- 远程分支使用虚线，本地分支使用实线。
- 已合并分支降低饱和度，但节点和标签仍可交互。
- 连线不得形成跨越大量行的对角线，不得穿过无关提交节点。

## 5. 数据与组件边界

### 5.1 共享 Git 拓扑

`CommitGraphLaneTopology` 继续是完整 Git 关系的唯一来源，包含全部提交、父边、Merge 边、refs 和浅克隆边界。

### 5.2 画布分支束索引

新增纯 Core 层分支束构建器，输入为完整拓扑、场景 Group 边界和强制可见哈希集合，输出稳定分支束和节点到分支束索引。构建只在以下情况执行：

- Git 快照变化；
- Group 成员变化；
- 搜索或选择改变强制可见集合；
- 用户显式展开或关闭分支束。

拖动、平移、缩放和切换线型不得重新计算 Git 拓扑。

### 5.3 传统可见分支投影

新增纯 Core 层上下文泳道选择器，输入为分支索引、视口宽度、HEAD、选中哈希和用户固定分支，输出当前可见分支与本地/远程聚合数量。

SwiftUI 只消费投影结果，不在绘制循环中遍历全部 refs。

### 5.4 持久化

场景 schema 增加以下兼容字段：

- 用户固定分支身份集合；
- 传统布局最近选择分支；
- 用户手动定位的普通节点哈希集合；
- 新布局算法版本。

旧场景读取后迁移到新布局版本。临时分支束展开、搜索词和悬停状态不持久化。

## 6. 性能设计

- 五万提交的 Git 拓扑、分支束索引和分支可见索引在后台构建。
- 主线程一次性安装不可变派生结果。
- 画布继续使用空间索引，只生成当前视口和预加载区域的节点、分支束与边路径。
- 概览层级只绘制聚合后的分支束、关键锚点和版本标识。
- 传统列表继续只创建可见行和预加载行。
- 分支搜索使用预构建的名称、哈希、作者、Tag、本地与远程 refs 索引。
- 切换传统可见分支只重建受影响泳道投影，不重读 Git。

性能目标：

- 五万提交和数百分支的首次派生保持在现有性能测试预算内；
- 局部视口查询不随总提交数量线性增长；
- 平移、缩放和滚动期间不执行全拓扑遍历；
- 搜索和分支切换不触发仓库刷新。

## 7. 异常与退化策略

- 仓库没有 refs 时，使用 HEAD 或最新提交作为主干回退。
- Detached HEAD 作为独立固定上下文显示。
- 用户固定分支已删除时，在刷新对账中移除该固定项并保留其他偏好。
- 分支束索引失败时退化为现有紧凑节点视图，不丢失提交。
- 传统可见分支投影异常时至少显示 HEAD 主干。
- 浅克隆缺失父提交继续显示明确边界端点，不进入普通分支束。
- 缓存或刷新失败继续显示上一次正确拓扑，并标记陈旧状态。

## 8. 测试范围

必须覆盖：

- 主干居中与左右分支稳定分配；
- 分支生命周期重叠时不占用同一轨道；
- 分支束只包含连续普通提交；
- 分叉、Merge、refs、Tag、搜索结果、Group 和浅边界不会被聚合；
- 点击和搜索可以展开分支束；
- 分支束展开不修改 Git 拓扑和用户 Group；
- 传统布局根据窗口宽度稳定返回四到八条泳道；
- HEAD、选中、固定、直接相关和最近活跃优先级；
- 本地与远程隐藏分支分别聚合；
- 选择隐藏分支只替换最低优先级临时泳道；
- 传统长父边和 Merge 边只在端点附近转弯；
- 旧场景迁移后保留 Group、区域、线型和固定端口；
- 五万提交与数百分支的派生、查询、搜索和滚动性能；
- 窄窗口、超长标题和大量分支标签不越界。

## 9. 验收标准

- 大型仓库初次进入时最新提交可读，不出现缩小到无法辨识的全历史画面。
- 远距离观看时能看清主干、主要分支束、分叉和 Merge 锚点。
- 用户能在两次操作内找到并显示任意本地或远程分支。
- 传统布局同时显示四到八条清晰泳道，其他分支可搜索且不会丢失。
- 连线不斜穿长段历史和无关提交节点。
- 切换视图、刷新、自动布局和聚焦主分支不会破坏 Group、折叠、区域和固定端口。
- 全量测试、Debug 构建、Release 构建及五万提交性能测试全部通过。
