# 提交图右键框选分组设计

## 目标

将提交分组入口改为画布内的右键框选操作，使用户可以直接圈选连续提交并创建分组，同时能通过边缘自动滚动选择当前窗口之外的内容。

## 交互规则

1. 仅在画布空白区域按住鼠标右键并拖动时启动框选。
2. 拖动距离达到 2 点后显示半透明选择框；右键单击不触发任何操作。
3. 与选择框相交的可见提交卡片实时高亮，并在指针附近显示已选数量。
4. 指针进入画布四边 40 点的热区后自动平移画布：
   - 越接近边缘，平移速度越快；
   - 支持上、下、左、右及对角方向；
   - 框选起点使用画布坐标保存，因此自动平移不会导致选择区域漂移；
   - 用户无需松开右键即可继续选择窗口之外的提交。
5. 松开右键后：
   - 少于 2 个提交时保留高亮并提示至少选择 2 个提交；
   - 提交不连通或已属于其他分组时保留高亮并说明原因；
   - 选择有效时直接打开分组名称输入框，确认后创建分组。
6. 工具栏原“创建分组”按钮改为“右键框选创建”的操作提示，不再依赖按钮触发创建。
7. 原有 Command 切换选择、Shift 追加选择仍保留为辅助能力，但不作为主要建组入口。
8. 自动布局、聚焦主分支、缩放、连线样式切换均不得改变已有分组及折叠状态。

## 性能与实现边界

1. 框选矩形、命中高亮和数量提示由 AppKit 交互层直接绘制，避免每次鼠标移动触发完整 SwiftUI 画布重绘。
2. 鼠标移动与边缘自动滚动合并到 `CADisplayLink` 帧调度中，每帧最多提交一次视口变化。
3. 自动滚动只更新视口；不重新计算 Git 拓扑、分组关系、聚合边或端口分配。
4. 框选只命中当前投影中的可见提交；折叠分组内部的隐藏提交不会被误选。
5. 本次遵循用户要求，不运行自动化测试，仅执行 Release 构建、签名和应用打包。
