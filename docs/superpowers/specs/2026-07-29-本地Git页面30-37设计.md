# GitMate 本地 Git 页面 30–37 设计规格

## 1. 目标

在 GitMate 中实现真实可用的本地 Git 工作流，覆盖工作区变更、暂存与提交、文件差异、Stash、合并/变基/拣选、冲突解决、远程仓库管理以及 Fetch/Pull/Push。

页面使用 macOS 系统 Git，遵循用户现有仓库配置、提交签名、Hooks、HTTPS 凭据和 SSH Agent。应用不得把任意用户文本拼接成 Shell 命令，也不得在命令、日志、缓存或远程地址中泄露凭据。

## 2. 页面范围

| 页码 | 页面 | 核心能力 |
|---|---|---|
| 30 | 工作区变更 | 查看、筛选、暂存、取消暂存和放弃变更 |
| 31 | 暂存与提交 | 文件/代码块暂存、填写提交说明、创建提交 |
| 32 | 文件差异 | 统一/并排差异、代码块操作、超大差异处理 |
| 33 | Stash 管理 | 创建、预览、Apply、Pop 和 Drop |
| 34 | 合并、变基与拣选 | 预检、开始、继续和中止 |
| 35 | 冲突解决 | 三方合并、逐块选择、手动编辑和标记解决 |
| 36 | 远程仓库管理 | Fetch/Push URL、跟踪关系和连接测试 |
| 37 | Fetch、Pull 与 Push | 远程差异预览、实时进度、取消和安全重试 |

## 3. 不在本阶段实现

- Submodule 与 Git LFS 管理，保留给页面 42。
- 创建、删除和重命名分支或标签，保留给分支与标签模块。
- 提交历史关系图，保留给页面 15。
- GPG/SSH 签名密钥生成、导入或管理。
- Git 全局配置编辑器。
- 裸 `--force` 推送。
- `reset --hard`、清理整个仓库和批量删除未跟踪文件。
- Reflog 恢复界面。
- 页面 10–29 的导航和业务实现。

## 4. 已确认的产品决策

- 开发真实 Git 功能，不是只做交互预览。
- 使用分级确认：
  - 暂存、取消暂存和普通提交直接执行。
  - 放弃修改、Stash Pop/Drop、合并、变基、拣选和 Push 必须先预检并确认。
  - 强制推送只允许 `--force-with-lease`，并使用更高级别确认。
- 自动沿用仓库远程协议：
  - HTTPS 使用钥匙串中的 GitHub Token。
  - SSH 使用 macOS SSH Agent/钥匙串。
  - 应用不保存 SSH 私钥。
- 提交签名遵循仓库或全局 Git 配置。本阶段不管理签名密钥。
- 冲突使用应用内三方合并编辑器，并提供外部编辑器兜底。
- 底层使用系统 Git CLI 和强类型服务层。
- 同一仓库同一时间只允许一个写操作。
- 必须支持大量变更文件，压力目标为 50,000 个变更条目。

## 5. 整体架构

### 5.1 分层

SwiftUI 页面不直接执行 Git、网络或文件系统操作。

```text
SwiftUI Views
    ↓ 用户意图 / 页面状态
LocalGitWorkspaceViewModel
    ↓ 强类型请求
RepositoryOperationCoordinator
    ├── LocalGitRepositoryReader
    ├── LocalGitMutationService
    ├── GitCredentialEnvironment
    └── GitOperationJournal
            ↓
      GitCommandBuilder
            ↓
   StreamingCommandExecutor
            ↓
      /usr/bin/git
```

### 5.2 核心组件

#### `LocalGitRepositoryReader`

只负责读取：

- 当前分支、HEAD、上游、领先/落后数量。
- 已暂存、未暂存、未跟踪、重命名、删除和冲突文件。
- 文件差异与代码块。
- Stash 列表和 Stash 差异。
- 分支与提交预检数据。
- 合并、变基、拣选进行状态。
- 冲突的 stage 1/2/3 内容。
- 远程地址、默认远程和跟踪关系。

读取接口返回值或 `AsyncSequence`，不改变仓库。

#### `LocalGitMutationService`

只负责强类型写操作：

- 暂存/取消暂存文件或代码块。
- 放弃文件或代码块变更。
- 创建提交。
- 创建、Apply、Pop、Drop Stash。
- 开始、继续和中止合并/变基/拣选。
- 保存冲突结果并标记解决。
- 添加、修改和删除远程。
- Fetch、Pull、Push。

服务不接受任意字符串命令，只接受经过校验的领域请求。

#### `RepositoryOperationCoordinator`

使用 `actor` 为每个仓库串行化写操作：

- 一个仓库同时最多有一个写操作。
- 不同仓库可以并行工作。
- 写操作期间允许读取进度和脱敏日志。
- 新读任务可以取消旧读任务。
- 合并、变基和拣选开始后使用“继续/中止”结束，不提供不安全的进程级取消。

#### `GitCommandBuilder`

根据强类型请求生成参数数组：

- 固定使用 `/usr/bin/git`。
- 通过 `Process.executableURL` 和 `arguments` 执行，不经过 Shell。
- revision、remote、branch 和 hash 使用独立校验规则。
- 文件路径通过 NUL 分隔 Pathspec 文件或标准输入传入。
- 提交说明通过标准输入传入，不放在命令行参数中。
- 不允许调用计划外子命令或附加任意参数。

#### `GitOutputParser`

优先使用机器稳定格式：

- `--porcelain=v2`
- `-z`
- 字段分隔符与记录分隔符
- `--numstat`
- `--format` 固定字段
- `--progress` 的结构化阶段解析

解析在主线程之外执行，并能增量产生轻量模型。

#### `GitCredentialEnvironment`

- HTTPS Token 从钥匙串按账户读取，仅放入子进程临时环境的认证头。
- 认证头不得写入 `arguments`、日志、错误对象、Journal 或远程 URL。
- SSH 不读取私钥文件，由系统 SSH Agent 处理。
- 连接测试只返回协议、主机和脱敏结果。

#### `GitOperationJournal`

只记录：

- 仓库稳定标识。
- 操作类型。
- 开始/结束时间。
- 脱敏阶段与进度。
- 成功、失败、冲突或取消结果。

Journal 不记录 Token、认证头、完整文件内容、补丁正文或未脱敏远程地址。

### 5.3 页面状态

`LocalGitWorkspaceViewModel` 负责仓库上下文和路由，各页面状态拆分为独立类型：

- `WorkingTreeState`
- `CommitComposerState`
- `FileDiffState`
- `StashState`
- `HistoryOperationState`
- `ConflictResolutionState`
- `RemoteManagementState`
- `RemoteTransferState`

子状态只依赖对应服务协议，避免单个 ViewModel 同时承担所有 Git 行为。

## 6. 安全与确认

### 6.1 操作分级

#### 直接执行

- 暂存文件或代码块。
- 取消暂存文件或代码块。
- 普通提交。
- 创建 Stash。
- Stash Apply。
- Fetch。

#### 预检后确认

- 放弃文件或代码块变更。
- Stash Pop。
- Stash Drop。
- 合并、变基和拣选。
- Pull。
- 普通 Push。
- 删除远程。

#### 高级确认

- `--force-with-lease` 推送。
- 覆盖二进制冲突文件。
- 放弃包含大量行或多个文件的修改。

高级确认必须显示仓库、分支、远程、提交范围和不可恢复影响。禁止裸 `--force`。

### 6.2 路径安全

- 仓库 URL 必须解析到现有本地 Git 工作树。
- 文件操作路径必须来源于 Git 索引或状态输出。
- 路径必须保持在仓库工作树内。
- 中文、空格、制表符、换行、前导短横线和其他合法 Git 文件名通过 NUL 分隔处理。
- 冲突结果写入前再次验证索引中的文件路径和文件类型。
- 临时 Pathspec 文件使用受限权限，操作结束后删除。

### 6.3 日志脱敏

统一过滤：

- `Authorization` 认证头。
- GitHub Token 与常见 PAT 形式。
- URL 用户信息。
- HTTPS Basic 认证内容。
- 可能包含凭据的 Git/SSH 错误片段。

页面可显示命令子类型和安全参数摘要，但不显示完整认证环境。

## 7. 大仓库与大量变更性能

### 7.1 两阶段状态读取

1. 先使用 `git status --porcelain=v2 -z --untracked-files=no` 返回已跟踪变更和分支信息。
2. 再使用 `git ls-files --others --exclude-standard -z` 后台扫描未跟踪文件。

用户无需等待未跟踪文件扫描完成即可开始处理已跟踪变更。

### 7.2 增量和虚拟化

- Git 输出流式解析。
- 每批最多 200 条状态更新页面。
- SwiftUI 使用 `LazyVStack`，只创建可见行。
- 状态项使用稳定 ID，禁止整列表反复重建选择状态。
- 搜索和筛选基于轻量索引，不预载 Diff。
- 文件系统变化使用 300ms 防抖。
- 每次刷新带版本编号，旧任务结果不得覆盖新任务。

### 7.3 Diff 限制

- 只加载当前选中文件或代码块的 Diff。
- 切换文件立即取消旧 Diff 任务。
- 超过 2,097,152 字节或 20,000 行时先显示摘要。
- 超大 Diff 支持分段加载和外部查看。
- 二进制文件不读取为文本。
- 内存不缓存未选中文件的完整补丁。

### 7.4 批量操作

- 批量暂存使用 `--pathspec-from-file` 和 `--pathspec-file-nul`。
- 不把数千个路径展开成命令行参数。
- 批次内部保留逐文件结果，失败时指出具体文件。
- UI 显示已处理/总数和当前文件。

### 7.5 性能验收

- 50,000 个变更条目能增量显示，主线程不执行 Git 解析或全量排序。
- 快速连续刷新只保留最后一代结果。
- 选择一个文件不会触发其他文件 Diff 读取。
- 搜索、滚动和勾选不因完整补丁缓存而显著增加内存。

## 8. 页面规格

### 8.1 页面 30：工作区变更

分组：

- 冲突。
- 已暂存。
- 未暂存。
- 未跟踪。

功能：

- 搜索文件路径。
- 按状态筛选。
- 单选、多选和全选当前筛选结果。
- 暂存所选/全部。
- 取消暂存所选/全部。
- 打开页面 32 查看 Diff。
- 放弃单个或多个文件修改。
- 手动刷新和文件系统变化自动刷新。

摘要显示：

- 当前分支和上游。
- 领先/落后数量。
- 文件数量。
- 新增/删除行数。
- 未跟踪扫描状态。

刷新时保留仍然存在的选择；已消失文件从选择中移除。

### 8.2 页面 31：暂存与提交

布局：

- 左侧：已暂存与未暂存文件。
- 中间：选中文件/代码块差异。
- 右侧：提交编辑器和提交前检查。

功能：

- 文件级暂存/取消暂存。
- 代码块级暂存/取消暂存。
- 提交标题与说明。
- 显示作者身份、分支和签名状态。
- 创建提交。
- Hook 失败后保留编辑内容和暂存区。
- 提交成功后显示哈希并刷新状态。

签名遵循 Git 仓库或全局配置。未启用签名时允许普通提交；已启用但签名失败时不降级为未签名提交。

### 8.3 页面 32：文件差异

功能：

- 统一差异与并排差异。
- 忽略空白变化。
- 上一个/下一个代码块。
- 暂存、取消暂存或放弃单个代码块。
- 显示重命名、文件模式和二进制变化。
- 超大 Diff 摘要与分段加载。

放弃代码块前必须显示将覆盖的行数并确认。补丁上下文已过期时不强行应用，刷新 Diff 后让用户重新选择。

### 8.4 页面 33：Stash 管理

功能：

- 创建带说明的 Stash。
- 选择是否包含未跟踪文件。
- 查看 Stash 文件和 Diff。
- Apply。
- Pop。
- Drop。

规则：

- Pop 与 Drop 必须确认。
- Apply/Pop 产生冲突时进入页面 35。
- Apply/Pop 失败不得删除原 Stash。
- Drop 失败后重新读取列表，不乐观移除。

### 8.5 页面 34：合并、变基与拣选

使用关系图和列表选择：

- 当前分支。
- 来源分支。
- 目标提交。
- 需要拣选的一个或多个提交。

预检：

- 工作区是否干净。
- 是否已有进行中的 Git 操作。
- 来源与目标是否存在。
- 领先/落后和提交范围。
- 预计修改文件。
- 可检测的潜在冲突。
- 远程是否需要先 Fetch。

工作区不干净时提供“先创建 Stash”，不自动丢弃或隐藏修改。

支持：

- 开始合并/变基/拣选。
- 继续。
- 中止。
- 冲突时进入页面 35。
- 应用重启后恢复进行状态。

### 8.6 页面 35：冲突解决

文本冲突使用三栏：

- 当前版本。
- 传入版本。
- 最终结果。

功能：

- 逐块采用当前。
- 逐块采用传入。
- 同时保留。
- 手动编辑最终结果。
- 保存文件。
- 标记为已解决。
- 打开外部编辑器。

二进制冲突只允许整文件选择当前或传入版本，并使用高级确认。

所有冲突解决前禁止继续操作。继续失败时保留解决结果和错误输出。

### 8.7 页面 36：远程仓库管理

功能：

- 显示全部远程。
- 显示 Fetch URL 和 Push URL。
- 添加远程。
- 修改远程名称或 URL。
- 删除远程。
- 查看默认拉取/推送远程。
- 查看分支跟踪关系。
- 测试 HTTPS/SSH 连接。

规则：

- URL 展示前脱敏。
- 自动识别协议。
- HTTPS 与 SSH 均沿用系统/账户环境。
- 删除远程前列出受影响跟踪分支。
- 连接测试失败不修改远程配置。

### 8.8 页面 37：Fetch、Pull 与 Push

执行前显示：

- 远程与分支。
- 将下载/上传的引用。
- 提交数量。
- 数据量估计。
- Pull 策略。
- 分支保护或远程拒绝风险。

Pull 默认遵循 `pull.rebase`、`pull.ff` 等 Git 配置，并明确显示将使用 fast-forward、merge 或 rebase。

数据量仅在不执行实际写操作即可安全估算时显示；无法低成本计算时显示“未知”，不得为了预估而重复打包整个仓库。GitHub 分支保护只在已有 GitHub API 上下文时预检；API 不可用时显示“未验证”，最终以远程服务器响应为准。

Push：

- 普通 Push 使用预检和确认。
- 强制推送只允许 `--force-with-lease`。
- 高级确认显示期望远程 OID 和可能被覆盖的提交。
- 多引用推送优先使用原子推送；远程不支持时必须提示差异。

进度显示：

- 当前阶段。
- 对象数量。
- 传输速度。
- 当前引用。
- 脱敏日志。

Fetch 和 Push 可取消。Pull 仅在 Fetch 阶段允许取消；进入本地整合后使用继续/中止流程。

## 9. 数据流

### 9.1 读取

1. 选择仓库。
2. Reader 验证工作树和 Git 元数据。
3. 先流式读取分支与已跟踪状态。
4. 页面立即显示首批结果。
5. 后台读取未跟踪文件和按需摘要。
6. 用户选择文件时读取对应 Diff。
7. 文件系统变化触发防抖刷新。

### 9.2 写入

1. ViewModel 生成强类型用户意图。
2. 服务执行预检。
3. 页面展示影响摘要和对应确认层级。
4. Coordinator 获取仓库写操作许可。
5. CommandBuilder 生成安全参数。
6. Executor 流式返回进度。
7. Parser 转换为结构化事件。
8. Journal 写入脱敏结果。
9. 释放写操作许可。
10. 只刷新受影响状态。

## 10. 异常与恢复

统一错误类型至少包含：

- 非 Git 仓库或仓库缺失。
- 仓库忙。
- Git 锁被占用。
- 工作区不干净。
- 补丁上下文过期。
- Hook 失败。
- 提交签名失败。
- 合并/变基/拣选冲突。
- HTTPS 授权失效。
- SSH Agent、主机指纹或权限失败。
- 网络中断和超时。
- 远程拒绝、非 fast-forward 和分支保护。
- 用户取消。
- Git 版本或能力不支持。
- 命令退出状态异常。

恢复规则：

- 不自动删除未知 Git 锁文件。
- 先判断是否存在仍运行的 Git 进程或操作状态。
- Hook/签名失败保留提交编辑内容和暂存区。
- 冲突保留工作树并进入页面 35。
- 授权失效请求重新授权。
- SSH 错误只显示安全诊断，不读取私钥。
- 网络中断不盲目重试 Push。
- 应用启动时读取 `MERGE_HEAD`、rebase 目录、`CHERRY_PICK_HEAD` 等状态并恢复继续/中止入口。

## 11. 集成方式

本阶段提供独立本地 Git 模块：

```swift
LocalGitRootView(
    repositoryURL: URL,
    credentialContext: GitCredentialContext,
    initialRoute: LocalGitRoute
)
```

模块不依赖页面 10–29 的具体实现。后续完整仓库工作区只需传入仓库 URL、账户上下文和目标路由。

开发与验收入口：

- `--preview-page 30...37` 使用确定性预览数据。
- `--local-repository <path>` 使用真实本地仓库。
- 自动化测试只在临时仓库和本地 Bare Remote 中执行写操作。

## 12. 视觉与窗口规范

- 主色调为白色。
- 正文使用高对比深色。
- 默认窗口 1180×760。
- 最小窗口 1040×680。
- 主窗口不产生纵向页面滚动。
- 文件列表、Diff、日志和编辑器只在各自面板内部滚动。
- GitHub 用户身份位置使用真实头像。
- 高风险操作使用红色层级、影响摘要和明确动词。
- 长任务始终显示进度、当前阶段和取消能力边界。

## 13. 测试策略

### 13.1 单元测试

- 命令构建器参数白名单。
- revision、remote、branch、hash 和路径校验。
- NUL 分隔状态解析。
- Diff、Stash、远程和进度解析。
- 日志脱敏。
- 操作分级与确认策略。
- 写操作串行和读任务取消。
- 旧刷新结果不覆盖新结果。

### 13.2 临时仓库集成测试

使用测试临时目录和真实系统 Git：

- 已暂存、未暂存、未跟踪、重命名和删除状态。
- 文件与代码块暂存/取消暂存。
- 普通提交和 Hook 失败。
- Stash 创建、Apply、Pop 和 Drop。
- 合并、变基、拣选成功、冲突、继续和中止。
- 文本与二进制冲突。
- 应用重启后的 Git 操作状态恢复。

测试不得在用户真实仓库执行写操作。

### 13.3 本地远程集成测试

使用本地 Bare Remote：

- 添加、修改和删除远程。
- Fetch。
- fast-forward Pull。
- merge/rebase Pull。
- 普通 Push。
- non-fast-forward 拒绝。
- `--force-with-lease` 成功和 lease 过期。
- 多引用原子推送能力处理。

测试不依赖公网。

### 13.4 性能测试

- 50,000 个状态条目的流式解析与分页。
- 特殊字符、中文、制表符、换行和前导短横线路径。
- 连续刷新取消和结果代次。
- 超大 Diff 摘要和分段加载。
- 批量 Pathspec 不超过系统命令长度。

### 13.5 UI 与视觉验收

逐页检查页面 30–37：

- 1180×760 默认窗口。
- 1040×680 最小窗口。
- 无主窗口纵向滚动。
- 大列表滚动和搜索保持响应。
- 确认层级与风险颜色正确。
- 冲突三方编辑器可用。
- 网络、认证、Hook、签名和冲突错误均有恢复入口。

## 14. 完成标准

- 页面 30–37 均可对临时或用户指定的真实本地仓库执行设计范围内操作。
- 所有 Git 命令由强类型构建器产生，不经过 Shell。
- 同一仓库写操作严格串行。
- Token、认证头和私钥不进入命令、日志、缓存或 Journal。
- 大量变更文件采用流式解析、分页和虚拟列表。
- 合并、变基和拣选能在冲突后继续或中止。
- 强制推送仅支持 `--force-with-lease`。
- 自动化测试通过，应用编译成功。
- 页面 30–37 原生窗口视觉验收通过。
