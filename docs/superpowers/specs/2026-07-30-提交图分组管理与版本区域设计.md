# 提交图分组管理与版本区域设计

## 目标

完善提交画布的分组管理能力，修复框选结束后临时状态残留的问题，增加用于标识大版本范围的独立区域，并让分支图例与真实 Git 数据一致。同时恢复 HTML 文件中 JavaScript 和页面资源的正常运行。

## 一、框选生命周期

### 根因

框选完成后，命中的提交被写入 `selectedHashes`。上一版设计故意保留无效选择以便用户继续调整，因此右下角的选择状态胶囊在鼠标松开后仍然存在。

### 调整

1. 框选矩形、节点描边和数量标识只在右键拖动期间显示。
2. 松开右键后立即结束框选视觉状态。
3. 新建分组选择有效时，提交选择只保留到创建弹窗结束：
   - 创建成功后清除；
   - 用户取消后清除。
4. 少于两个提交、选择不连通或与其他分组冲突时，显示具体原因并清除临时选择。
5. 删除画布右下角常驻的框选状态胶囊；操作说明保留在工具栏帮助中。

## 二、已有分组管理

### 入口

右键单击分组标题区域打开原生菜单，提供：

- 重命名；
- 添加提交；
- 删除分组。

双击分组标题仍用于展开或折叠，不改变现有操作。

### 重命名

1. 打开包含当前名称的输入弹窗。
2. 名称去除首尾空白后保存。
3. 空名称使用默认名称“提交分组”。
4. 只更新分组标题，不修改成员、坐标、折叠状态、端口或连线。

### 添加提交

1. 选择“添加提交”后进入一次性添加模式。
2. 工具栏显示正在编辑的分组名称，按 `Esc` 可取消。
3. 用户在画布空白处按住右键框选要增加的提交。
4. 新成员与原成员取并集后必须满足：
   - 至少包含两个提交；
   - 所有成员组成连通的 Git 子图；
   - 不包含属于其他分组的提交。
5. 已属于当前分组的提交允许被框中，但不会重复添加。
6. 添加成功后退出编辑模式；失败时显示原因并退出本次一次性操作。

### 删除分组

1. 删除前显示确认弹窗。
2. 删除只解散分组，不删除任何 Git 提交。
3. 组内成员使用删除前的绝对画布位置恢复为普通提交节点。
4. 删除后重建受影响的跨组边和端口，未受影响的端口继续复用。

### 禁止嵌套

1. `CommitGraphSceneState.groups` 保持扁平集合，不增加父分组字段。
2. 框选只返回提交哈希，不返回分组 ID。
3. 创建和更新分组时在核心层检查成员归属；属于其他分组的提交一律拒绝。
4. UI 层的过滤只是交互提示，核心层校验是最终约束。

## 三、大版本区域标识

### 定义

区域标识是提交画布背景上的视觉注释，用于标记例如 `v1.0`、`v2.0 Beta` 等大版本范围。它不拥有提交，也不参与 Git 拓扑、分组、折叠、聚合边或端口分配。

### 数据模型

新增独立模型：

```swift
struct CommitGraphRegionMarker {
    let id: UUID
    var title: String
    var colorHex: String
    var origin: GraphPoint
    var size: GraphSize
}
```

区域使用画布坐标保存，随画布一起平移和缩放。颜色保存为标准十六进制字符串，确保重新打开仓库后保持一致。

### 创建

1. 工具栏增加“创建区域标识”。
2. 点击后进入一次性区域创建模式。
3. 下一次在画布空白处右键拖动创建区域矩形，此时不执行提交分组框选。
4. 松手后打开编辑弹窗，填写区域名称并通过颜色选择器设置颜色。
5. 范围过小时取消创建并提示重新框选。
6. 创建完成或按 `Esc` 后退出区域创建模式。

### 编辑

1. 拖动区域标题栏移动区域。
2. 拖动右下角手柄调整区域宽高。
3. 右键区域标题打开菜单：
   - 重命名；
   - 更改颜色；
   - 删除区域。
4. 颜色可以随时更改并立即更新画布。
5. 区域允许彼此重叠，也允许在视觉上覆盖分组；这些重叠不表达嵌套关系。

### 绘制顺序

绘制层级从后到前：

1. 网格；
2. 区域标识；
3. 展开分组背景；
4. 连线；
5. 提交节点；
6. 折叠分组；
7. 框选和交互提示。

## 四、动态分支图例

1. 删除固定的“主分支、功能分支、发布分支”语义。
2. 从当前窗口中可见提交的 decorations 提取真实本地和远程分支名。
3. 图例颜色使用对应提交轨道的 `colorIndex`，与画布保持一致。
4. 直接显示最多三个分支，剩余分支通过“更多”菜单查看。
5. 合并关系使用合流图标和“合并”文字，不再使用容易被误解为分支颜色的橙色横线。
6. 图例使用独立的小型标签，不再使用包含全部内容的大胶囊外框。
7. 当前窗口没有分支引用时，仅显示合并关系说明。

## 五、HTML 完整预览

1. `WKWebView` 开启 JavaScript。
2. 保留 HTML 原始文档、内联脚本和外部脚本引用。
3. 使用当前仓库和所选文件目录作为基础地址，使相对 CSS、图片和脚本可以加载。
4. 内容安全策略允许：
   - 内联、`data:`、`blob:`、本地及 HTTP/HTTPS 脚本；
   - HTTP/HTTPS、WebSocket 页面连接；
   - 本地及网络图片、样式、字体和媒体。
5. 网页导航在预览内部完成，不接入 GitMate 原生方法或数据接口。
6. 界面明确显示“脚本已启用”，避免继续展示错误的安全状态说明。
7. SVG 继续使用受限的静态预览策略，不因为 HTML 脚本设置而执行 SVG 脚本。

## 六、持久化兼容

1. 场景状态新增 `regions` 字段。
2. 旧场景文件缺少该字段时按空数组解码，已有节点、分组、端口和连线样式保持不变。
3. 增加字段采用向后兼容解码，不因新增区域功能破坏旧仓库的画布状态。
4. 分组重命名、成员增加、分组删除、区域创建和区域编辑都复用现有延迟保存机制；交互结束时立即刷新投影。

## 七、错误处理

- 无效分组成员：说明必须选择连通且未属于其他分组的提交。
- 目标分组不存在：结束编辑模式并提示分组已被删除。
- 区域范围过小：不创建数据，只提示重新框选。
- HTML 相对资源不存在：由网页正常显示资源加载失败，不影响源码模式。
- 场景保存失败：沿用现有场景警告，不丢弃当前内存中的编辑结果。

## 八、验收标准

1. 鼠标松开后不再残留图一所示的框选状态胶囊。
2. 分组可重命名、添加提交和删除，删除不影响 Git 数据。
3. 任何入口都无法创建分组嵌套。
4. 区域标识可创建、移动、缩放、重命名、改色和删除。
5. 自动布局、聚焦分支、缩放和线型切换不改变分组及区域状态。
6. 图例显示真实可见分支，不再使用固定分支类型。
7. HTML 页面脚本和相对资源能够在完整网页预览中运行。
