# 仓库总览、介绍接入与里程碑创建修复设计

## 1. 目标

本次改动只处理两个范围：

1. 将已经完成的仓库总览和 README 介绍接入分支、标签、议题共用的仓库工作区侧边栏，取消这两个入口的灰色禁用状态。
2. 修复新建里程碑时 GitHub 返回 `422 Invalid request` 的问题，并让失败状态保留用户输入、显示可操作的错误信息。

本次不开发 Actions、Releases、Packages，也不重写页面 12–13 的视觉和数据逻辑。

## 2. 已确认现状

- 页面 12 仓库总览和页面 13 README 介绍已经实现，并且已经接入本地仓库、GitHub 在线摘要、缓存、README 解析和图片授权。
- 新仓库工作区的 `RepositorySidebarView` 将“总览”和“介绍”的路由设置为 `nil`，所以两个按钮被禁用。
- 新仓库工作区与旧全局工作区使用两套路由，但指向同一个账户和仓库。
- 新建里程碑使用 `POST /repos/{owner}/{repo}/milestones`。
- 当前 `MilestoneInput` 会把未填写的 `description` 和 `due_on` 显式编码为 `null`。
- GitHub 创建里程碑接口把 `description` 和 `due_on` 定义为可选字符串；创建请求应在未填写时省略这些字段。
- 当前保存动作先关闭编辑弹窗，再异步请求 GitHub，失败后只能在页面顶部显示通用错误，用户输入已经丢失。

## 3. 方案选择

### 3.1 采用方案：在当前仓库工作区原生接入

仓库工作区增加总览和介绍路由，并复用现有 `RepositoryOverviewView`、`READMEView`、对应 ViewModel、内容缓存和图片授权。

采用该方案的原因：

- 点击侧边栏后不切换外壳，账户头像、仓库卡片和导航位置保持不变。
- 继续使用既有真实数据与缓存，不产生第二套总览实现。
- 后续 Actions、Releases、Packages 可以沿用相同的仓库路由模式。

### 3.2 不采用方案

- **退出仓库工具并跳回旧工作区：** 实现较快，但侧边栏和页面外壳会突然变化，用户会误以为离开了当前仓库。
- **复制一套总览与 README：** 会产生重复页面、重复请求和长期维护分叉。

## 4. 导航与页面结构

### 4.1 仓库路由

`RepositoryWorkspaceRoute` 增加：

- `overview`：页面 12，仓库总览。
- `readme`：页面 13，README 介绍。

现有页面 16–23 编号和路由保持不变。仓库工具仍默认进入分支页，避免改变用户现有启动流程。

### 4.2 侧边栏行为

- “总览”绑定 `overview`，恢复正常文字、图标和点击状态。
- “介绍”绑定 `readme`，恢复正常文字、图标和点击状态。
- 当前页使用现有蓝色选择背景。
- 从总览进入 README 时在当前仓库工作区内切换。
- 从总览进入文件与提交、提交图等尚未纳入 `RepositoryWorkspaceRoute` 的既有页面时，通过父级导航回到对应的 `WorkspaceRoute`，不复制页面。
- “返回仓库工作区”继续返回全局工作区，并保留当前账户和仓库上下文。

### 4.3 页面复用

仓库工作区不直接复制页面代码，而是为已有页面提供运行上下文：

- 当前 `Repository`。
- 当前 `GitHubAccount`。
- 钥匙串中的访问令牌。
- 现有 `WorkspaceContentService`。
- `READMEImageAuthorization`。
- 授权失效回调与重新同步回调。

总览和介绍继续使用既有缓存、后台刷新、离线内容和错误面板行为。

## 5. 运行时结构

`RepositoryWorkspaceRuntimeFactory` 不再只返回 `RepositoryWorkspaceViewModel`，而是组装一个仓库工作区运行上下文。该上下文至少包含：

- 页面 16–23 使用的 `RepositoryWorkspaceViewModel`。
- 页面 12–13 使用的仓库内容加载器。
- README 图片授权所需的账户与令牌上下文。
- 跳转到父级 `WorkspaceRoute` 的回调入口。

正式运行复用 `WorkspaceRuntimeDependencies.contentService(for:)`，预览模式使用隔离演示加载器，不能访问真实 GitHub、钥匙串或本地仓库。

## 6. 里程碑创建根因与修复

### 6.1 根因证据与判断

创建和更新里程碑共用同一个编码逻辑。该逻辑为了支持更新时清空描述或截止日期，会对空值编码 `null`；但创建接口把这两个字段定义为可选字符串。只填写标题创建里程碑时，请求包含：

```json
{
  "title": "v1.0",
  "description": null,
  "state": "open",
  "due_on": null
}
```

用户实际操作由当前代码发出上述负载，GitHub 返回 `422 Invalid request`。因此本次把“创建与更新错误共用空值编码语义”作为根因修复；同时补齐字段级错误解析。如果 GitHub 还有仓库策略或字段校验，界面将显示具体原因，而不是继续退化成通用错误。

接口依据：[GitHub REST API：Create a milestone](https://docs.github.com/en/rest/issues/milestones?apiVersion=2022-11-28#create-a-milestone)。

### 6.2 请求编码分离

领域层继续使用一个 `MilestoneInput` 表达表单内容，但传输层使用不同负载：

- **创建负载：** `title` 和 `state` 始终发送；空的 `description`、`due_on` 直接省略。
- **更新负载：** 支持显式发送 `null`，用于清除已有描述或截止日期。
- 截止日期继续使用 GitHub 接受的 UTC ISO 8601 格式 `YYYY-MM-DDTHH:MM:SSZ`。

### 6.3 保存交互

- 点击保存后，编辑弹窗保持显示并进入提交中状态。
- 提交期间禁用重复保存和取消，保存按钮显示进度。
- 创建成功后关闭弹窗，并将新节点追加到里程碑画布。
- 创建失败后保留标题、描述、状态和截止日期。
- 错误显示在弹窗内，不依赖被弹窗遮挡的页面顶部横幅。
- 失败后允许直接修改并重试。

### 6.4 错误信息

GitHub 422 错误解析保留：

- HTTP 状态。
- GitHub 返回的主消息。
- `resource`、`field`、`code` 和字段消息。

界面优先显示具体字段错误；没有字段详情时显示中文回退信息。403 权限错误明确提示令牌需要仓库 Issues 或 Pull requests 写权限。

## 7. 数据流

### 7.1 总览与介绍

```text
侧边栏点击
  → RepositoryWorkspaceRoute
  → 仓库工作区页面容器
  → 既有 RepositoryOverviewViewModel / READMEViewModel
  → 共享 WorkspaceContentService
  → 本地 Git、缓存与 GitHub REST
```

### 7.2 新建里程碑

```text
编辑表单
  → MilestoneInput
  → RepositoryWorkspaceViewModel.createMilestone
  → 创建专用请求负载（省略空可选字段）
  → GitHub REST
  → 成功追加节点 / 失败保留表单与错误
```

## 8. 状态与异常处理

- 切换总览与介绍时取消上一页未完成加载，慢响应不能污染当前页面。
- 已有缓存先显示，后台刷新失败时保留缓存并显示非阻塞提示。
- 授权失效沿用现有重新授权流程。
- 离线时总览与介绍继续显示最近成功内容；没有缓存时显示可重试空状态。
- 里程碑创建任务只能同时存在一个，避免重复创建。
- 用户离开里程碑页面时取消未完成的界面任务；已提交到 GitHub 的请求结果仍通过重新加载对齐。

## 9. 测试与验收

### 9.1 自动测试

- `RepositoryWorkspaceRoute` 的总览和介绍映射到页面 12、13。
- 侧边栏总览和介绍不再禁用，选中状态正确。
- 总览与介绍使用当前仓库上下文和共享加载器。
- 总览进入 README 时保持当前仓库工作区。
- 创建里程碑未填写描述和截止日期时，请求 JSON 不包含对应字段。
- 创建里程碑填写截止日期时，使用 UTC ISO 8601 字符串。
- 更新里程碑清除截止日期时，请求显式包含 `"due_on": null`。
- 422 字段详情被完整解析并转为可读错误。
- 创建失败时 ViewModel 不追加节点，表单状态保持可重试。
- 连续点击保存只发送一次请求。

### 9.2 原生视觉验收

- 固定 1180 × 760 窗口下，总览和介绍内容只在内部滚动。
- 侧边栏不再出现灰色的总览和介绍。
- 页面 12、13 与页面 16–23 共享同一仓库侧边栏和白色主视觉。
- 新建里程碑提交中、成功和 422 失败状态均在弹窗内完整显示。
- 失败后所有输入仍然存在，可直接修改并重试。

## 10. 交付范围

本次交付包括：

- 总览与介绍侧边栏接入。
- 仓库工作区复用页面 12–13 所需的运行时装配。
- 里程碑创建负载修复。
- 里程碑保存状态和字段级错误反馈。
- 自动测试、中文验证清单和新的本地测试包。

本次明确不包括：

- Actions、Releases、Packages。
- 总览或 README 的重新设计。
- 文件与提交、提交图迁移到 `RepositoryWorkspaceRoute`。
- GitHub Token 权限自动修改。
