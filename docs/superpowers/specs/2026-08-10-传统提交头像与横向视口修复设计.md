# 传统提交头像与横向视口修复设计

## 背景

传统提交布局目前存在三个相互关联的问题：

1. 提交列表会预加载当前窗口上下方的行，但头像是独立 SwiftUI 覆盖层，未按提交内容视口裁剪。滚动后，负坐标头像会穿透到“工作区变更”和分支栏。
2. 提交作者无法从 GitHub noreply 邮箱或当前账户登录名识别时，只显示统一的系统人物图标，无法区分作者。
3. 上下文泳道改造移除了原有横向偏移状态。当前交互层仍能读取触控板横向增量，但增量被丢弃，窄窗口下无法查看完整的分支图、头像和提交文字。

## 目标

- 头像只能出现在提交历史内容区，不得覆盖工作区变更、分支栏或其他固定头部。
- 可识别作者时显示真实 GitHub 头像；无法识别时显示稳定的作者首字母头像。
- 不增加 GitHub API 请求，不引入新的限流风险。
- 提交历史下方内容层支持整体左右拖动；分支线、节点、头像和提交信息保持同步移动。
- 支持鼠标拖动和触控板横向滚动，且横向偏移始终限制在有效边界内。
- 保持现有垂直虚拟化、提交选择、分支选择和未提交工作区摘要语义不变。

## 非目标

- 不通过逐提交 GitHub REST API 查询作者身份。
- 不改变 Git 提交模型、提交拓扑或分支投影算法。
- 不改动画布式提交图交互。
- 不为传统布局新增永久可见的系统滚动条。

## 方案概览

采用“固定头部 + 可裁剪虚拟内容视口”结构：

1. 工作区变更行和分支上下文栏继续由外层纵向布局固定显示。
2. 提交内容区根据窗口宽度计算虚拟内容宽度。窗口足够宽时内容宽度等于窗口宽度；窗口较窄时保留满足图轨、头像和提交信息可读性的最小宽度。
3. Canvas、头像层和无障碍提交行放入同一个内容容器，共享同一个横向偏移。
4. 交互层固定覆盖可见窗口，鼠标拖动或横向滚动只更新横向偏移，不移动固定头部。
5. 内容容器在 GeometryReader 边界处裁剪，预加载元素即使具有负坐标也无法越界绘制。

## 头像解析

新增纯头像身份解析逻辑，输入为提交作者姓名、作者邮箱、当前账户登录名、当前账户显示名称和当前账户头像地址。

解析顺序：

1. 作者邮箱符合 GitHub noreply 规则时，从邮箱提取登录名并使用 `https://github.com/<login>.png`。
2. 作者姓名与当前账户登录名或当前账户显示名称进行忽略大小写和变音符号比较；匹配时复用当前账户真实头像。
3. 其余作者不发起身份查询，生成最多两个字符的首字母标识和稳定配色。

头像加载失败时继续显示同一个首字母回退，不显示空白，也不退回所有作者相同的系统人物图标。

## 横向视口

新增可独立测试的纯横向视口计算：

- `contentWidth(viewportWidth:)`：返回不小于窗口宽度的内容宽度。
- `maximumOffset(contentWidth:viewportWidth:)`：返回最大横向偏移。
- `clampedOffset(_:contentWidth:viewportWidth:)`：将偏移限制在 `0...maximumOffset`。
- 窗口尺寸或可见分支槽数量变化时重新夹紧现有偏移，不自动跳回最左侧。

虚拟内容最小宽度使用确定公式：图轨宽度取 `max(220, laneContentWidth + 12)`，提交头像与文字信息区保留 560 点，两者相加后再与窗口宽度取最大值。该公式使四条泳道的窄窗口不会压缩提交文字，也使十个上下文槽仍能完整横向查看。

交互规则：

- 触控板横向滚动直接修改横向偏移。
- 鼠标按下后移动超过系统拖动阈值进入横向拖动；拖动期间不触发提交选择。
- 鼠标未形成拖动时，松开后仍按原逻辑选择对应提交行。
- 拖动时使用增量更新，不重算 Git 拓扑、分支目录或传统布局。
- 到达边界后继续拖动不会产生回弹或空白区域。

## 可见行与裁剪

Canvas 继续使用带预加载范围的行集合，保证滚动时连线和背景无闪烁。

头像层和无障碍交互层只使用真实窗口可见行范围，不创建窗口外头像。整个内容容器额外执行边界裁剪，形成双重保护：

- 行过滤减少不必要的 SwiftUI 视图和头像下载任务。
- 容器裁剪防止任何负坐标或超出宽度的内容覆盖固定头部。

## 状态与数据流

- 横向偏移仅属于传统页面当前呈现状态，不写入提交图场景，不影响画布视口。
- 当前账户显示名称从工作区会话沿 `WorkspaceRootView`、`CommitGraphView` 传到传统布局。
- Canvas、头像和无障碍层只接收计算后的内容宽度与横向偏移，不各自保存位置状态。
- 切换仓库或重建传统页面时使用默认左侧位置；同一页面尺寸变化时保留并夹紧当前偏移。

## 错误与退化处理

- 头像地址无效或网络加载失败：显示作者首字母头像。
- 作者姓名为空：从邮箱本地部分提取首字母；仍为空时显示 `?`。
- 内容宽度或窗口宽度非有限值：退化为无横向偏移。
- 提交数为零：不创建头像层，横向偏移保持零。
- 只有一条泳道或窗口足够宽：最大偏移为零，拖动不改变页面位置。

## 测试策略

先写失败测试，再实现：

1. 头像解析覆盖 GitHub noreply、当前登录名、当前显示名称、普通邮箱首字母和空作者。
2. 头像加载失败继续保留首字母回退。
3. 横向内容宽度不小于窗口宽度。
4. 横向偏移正确夹紧左边界、右边界和窗口扩大后的新边界。
5. 真实可见头像行不包含预加载但位于窗口外的行。
6. 鼠标拖动超过阈值时不选择提交；普通点击仍选择提交。
7. Debug 构建、核心测试和 Release 打包校验继续通过。

## 验收标准

- 任意垂直滚动位置下，工作区变更和分支栏中都不会出现提交头像。
- 当前账户提交可显示账户真实头像；GitHub noreply 作者可显示对应 GitHub 头像；其他作者显示可区分的首字母头像。
- 在窄窗口中按住提交内容区左右拖动时，分支线、节点、头像和提交信息同步移动。
- 拖动不会误开提交详情，单击仍能正常打开提交详情。
- 横向拖动不会露出内容区外的空白，也不会移动顶部固定区域。
