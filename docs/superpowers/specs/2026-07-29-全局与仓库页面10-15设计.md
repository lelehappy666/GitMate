# GitMate 全局与仓库页面 10–15 设计规格

## 1. 目标

在现有登录、账户与首次同步功能之上，开发全局工作区和仓库核心浏览能力。用户登录并完成首次同步后进入全局工作台，可以查看全部仓库、打开仓库、浏览 README、文件、提交历史和节点式提交图。

本阶段采用本地优先混合模式：

- 本地 Git 提供文件、提交、差异、分支关系和提交图。
- GitHub API 补充真实用户头像、在线状态、议题、拉取请求和 Actions 摘要。
- 网络不可用时仍可浏览本地仓库与已缓存内容。

## 2. 范围

### 2.1 包含页面

| 页码 | 页面 | 主要能力 |
|---|---|---|
| 10 | 全局工作台 | 今日焦点、仓库健康、GitHub 状态和同步摘要 |
| 11 | 仓库封面墙 | 海报式仓库网格、搜索、筛选和排序 |
| 12 | 仓库总览 | 仓库元数据、同步状态、最近提交和快捷入口 |
| 13 | README 介绍 | 完整 Markdown 渲染、目录、图片和外部链接 |
| 14 | 文件与提交 | 文件树、内容查看、提交历史、差异和复制哈希 |
| 15 | 无限画布提交图 | 提交节点、分支与合并连线、缩放拖拽和详情弹窗 |

### 2.2 不包含

- 议题、里程碑和拉取请求详情页，即页面 19–29。
- 分支切换、重置、拣选、合并、变基和其他 Git 写操作。
- Actions、Releases、安全、洞察和仓库设置详情。
- 已移除的收件箱和项目模块。

页面 10 可以展示议题、拉取请求和 Actions 数量，但本阶段不实现对应详情工作流。

## 3. 已确认的产品决策

- 使用按可运行功能切片的开发方式，不先制作整套静态页面。
- 页面 10–15 只提供真实浏览与安全操作。
- 文件、README、列表和画布在各自面板内部滚动或移动，主窗口不产生纵向滚动。
- 主色调保持白色、浅灰层级、少量蓝色强调和高对比深色文字。
- GitHub 用户身份位置使用真实用户头像。
- 页面 15 的提交详情在点击节点后弹出，不固定占用右侧空间。
- README 封面跳过徽章、状态图和小图标，选择第一张有效大图。
- 没有有效 README 图片时自动生成统一风格的仓库封面。
- 封面图片下载后保存到本地磁盘缓存。

## 4. 应用结构

登录完成后由 `AppShell` 接管主窗口：

- 左侧显示固定的全局与仓库导航。
- 右侧根据工作区路由显示页面 10–15。
- 全局页面使用当前账户上下文。
- 仓库页面同时使用当前账户和当前仓库上下文。

页面使用独立 ViewModel，不直接操作 Git、网络、钥匙串或文件系统。

## 5. 核心服务

### 5.1 LocalRepositoryCatalog

职责：

- 维护远程仓库编号与本地目录的对应关系。
- 提供仓库名称、路径、大小、同步模式和同步状态。
- 识别本地目录缺失、Git 数据损坏和未完成同步。
- 为全局工作台和仓库封面墙提供统一仓库列表。

### 5.2 LocalGitReader

只执行读取类 Git 命令：

- `git status`
- `git log`
- `git show`
- `git diff`
- `git ls-tree`
- `git branch --all`
- `git tag`

职责：

- 读取工作树摘要和默认分支。
- 构建文件树并读取指定版本的文件内容。
- 解析提交作者、头像关联信息、父提交、分支和标签。
- 生成文件差异统计与补丁。
- 构建页面 15 所需的提交关系图。

所有参数以数组传递，不拼接 Shell 字符串。提交信息、路径和作者输入不得作为可执行内容。

### 5.3 GitHubWorkspaceAPI

职责：

- 获取当前账户与仓库在线元数据。
- 获取议题、拉取请求和 Actions 摘要数量。
- 获取默认分支、主要语言、仓库可见性和远程更新时间。
- 获取 README 原始内容和远程图片地址作为本地缺失时的后备数据。
- 识别 API 限流、权限不足和授权失效。

Token 继续只从 macOS 钥匙串读取，不进入缓存、日志、命令参数或 Git 远程地址。

### 5.4 RepositoryContentService

职责：

- 合并本地 Git、GitHub API 和缓存数据。
- 本地数据与远程数据冲突时，以本地 Git 内容为文件和提交事实来源。
- GitHub API 只补充在线状态和远程元数据。
- 网络失败时返回本地数据，并附带离线状态，而不是使整个页面失败。

### 5.5 WorkspaceCache

缓存内容：

- 账户和仓库摘要。
- 最近一次在线状态和更新时间。
- 仓库封面选择结果。
- README 目录和渲染辅助数据。

不缓存：

- Token。
- Git 命令环境。
- 未脱敏的错误日志。
- 可以直接从本地 Git 重新读取的大型提交图。

## 6. 页面规格

### 6.1 页面 10：全局工作台

页面以“今日焦点”作为首屏视觉中心，避免所有指标平均分布。

内容：

- 当前账户真实头像、账户和服务器。
- 今日焦点卡片。
- 仓库总数、健康状态、同步失败和本地未提交摘要。
- 议题、拉取请求与 Actions 数量。
- 跨仓库最近活动。
- 仓库健康摘要。

行为：

- 点击仓库进入页面 12。
- 点击“全部仓库”进入页面 11。
- 摘要数据分模块刷新，单个模块失败不阻塞页面。
- 不显示收件箱和项目入口。

### 6.2 页面 11：仓库封面墙

内容：

- 自适应电影海报式网格。
- 仓库名、所有者、可见性、主要语言、大小和同步状态。
- 搜索框。
- 可见性、语言、同步状态筛选。
- 最近更新、名称和大小排序。

封面规则：

1. 解析 README 中的 Markdown 图片与允许的 HTML 图片。
2. 排除常见徽章域名、SVG 状态图、尺寸过小图片和明显图标。
3. 选择第一张有效大图。
4. 下载并保存磁盘缓存。
5. 失败时使用仓库名、语言色和稳定哈希生成封面。

行为：

- 点击封面进入页面 12。
- 图片加载失败不改变卡片尺寸。
- 列表只在内容面板内部滚动。

### 6.3 页面 12：仓库总览

内容：

- 仓库名、可见性、默认分支、主要语言、大小和远程地址。
- 本地同步状态、最后同步时间和未提交数量。
- 最近提交列表。
- 议题、拉取请求和 Actions 摘要。
- README 简介。
- 页面 13–15 的快捷入口。

行为：

- 本地仓库不存在时显示“重新同步”状态，不隐藏远程仓库。
- README 简介从实际 README 渲染。
- 所有用户身份显示真实头像或统一头像占位。

### 6.4 页面 13：README 介绍

支持：

- 标题、段落、列表、引用和分隔线。
- 表格、任务列表和代码块。
- 行内代码、强调、删除线和链接。
- 本地图片与允许的远程图片。
- 自动目录和标题定位。

安全规则：

- 不执行脚本。
- 不加载不支持的嵌入内容。
- 外部链接显示外部跳转标识。
- 危险协议不允许打开。
- 超大图片按内容宽度缩放。

### 6.5 页面 14：文件与提交

文件模式：

- 分层文件树。
- 路径搜索。
- 文件内容查看和语法高亮。
- 二进制文件、超大文件和无法解码文件使用明确空状态。
- 显示文件路径、大小和最后提交。

提交模式：

- 分页提交历史。
- 作者头像、姓名、时间、哈希和分支标签。
- 作者、关键词和时间筛选。
- 查看提交说明、文件变更与差异。
- 复制提交哈希。

本阶段不允许编辑、暂存、提交或切换分支。

### 6.6 页面 15：无限画布提交图

画布能力：

- 自由拖拽和平移。
- 以鼠标位置为中心缩放。
- 自动布局。
- 聚焦当前分支。
- 分支颜色图例。
- 缩略图。
- 按需加载更早提交。

节点能力：

- 显示提交标题、作者头像、短哈希、分支或标签。
- 父子关系使用实线。
- 合并关系使用明确曲线。
- 当前选中节点使用蓝色高亮。

详情能力：

- 点击节点后弹出提交详情。
- 显示作者、签名状态、完整说明、父提交、文件统计和差异入口。
- 关闭弹窗后保留画布位置与缩放比例。

大型仓库默认只加载最近 200 个节点，到达画布边界后分批加载更早提交。

## 7. 数据流

1. 页面先读取本地缓存并立即显示。
2. 后台并行读取本地 Git 和 GitHub API。
3. `RepositoryContentService` 合并结果。
4. ViewModel 按模块增量更新页面。
5. 新数据写入允许的缓存。
6. 网络失败时保留本地结果并显示离线状态。

仓库切换会取消旧仓库的后台读取任务，避免旧结果覆盖新页面。

## 8. 异常处理

### 8.1 页面级空状态

- 当前账户没有仓库。
- 搜索或筛选没有结果。
- 本地仓库尚未同步。
- README 不存在。
- 提交历史为空。

### 8.2 面板级错误

- 单个 GitHub 摘要接口失败。
- 单个 README 图片失败。
- 单个仓库 Git 数据损坏。
- 单个文件无法读取。

其他面板继续工作。

### 8.3 全局状态

- 离线：显示全局横幅，本地浏览继续可用。
- API 限流：显示预计恢复时间并暂停自动请求。
- 授权失效：复用页面 9 的重新授权流程并保留当前仓库路由。

## 9. 性能要求

- 页面 10 与页面 11 优先显示缓存，不等待全部网络请求。
- 文件树、提交历史和仓库网格分页或惰性加载。
- 提交图首批最多加载 200 个节点。
- Git 和文件系统读取不在主线程执行。
- 封面下载限制并发数量，并使用磁盘缓存。
- 取消页面或切换仓库时停止不再需要的任务。

## 10. 测试与验收

### 10.1 自动化测试

- 仓库目录映射和状态识别。
- Git 状态、文件树、提交、差异和关系图解析。
- GitHub 与本地数据合并。
- README 封面筛选和回退封面。
- 缓存读写、过期和离线回退。
- API 限流、权限不足和授权失效。
- 文件树与提交分页。
- 提交图布局、合并连线、缩放边界和按需加载。
- 点击节点弹出详情并保留画布状态。
- Token 不进入命令参数、日志、缓存和远程地址。
- README 不执行脚本或危险链接。

### 10.2 视觉验收

- 支持 `--preview-page 10` 到 `--preview-page 15`。
- 在 1180×760 默认窗口逐页检查。
- 在 1040×680 最小窗口逐页检查。
- 主窗口无纵向滚动。
- 面板无重叠或底部操作区遮挡。
- 文字保持高对比。
- 用户位置显示真实头像。
- 页面 15 详情以弹窗形式出现。

### 10.3 交付方式

按以下可运行切片提交：

1. 共享应用壳与数据基础。
2. 全局工作台。
3. 仓库封面墙。
4. 仓库总览与 README。
5. 文件与提交。
6. 无限画布提交图。
7. 回归验证、`.app` 预览和中文验收文档。

所有文档和 Git 提交使用中文。
