# 提交分组折叠与多格式文件预览设计

## 目标

本轮在现有 macOS GitMate 项目中完成三类改进：

1. 修复文件源码预览在内容较短时未靠左的问题。
2. 扩展图片、PDF、安全 HTML 和常见脚本文件预览。
3. 在现有矢量提交画布上增加提交分组、折叠、拖动、稳定端口、跨组边聚合和两种动态连线样式。

实现必须复用现有 Swift、SwiftUI、AppKit、Canvas、Observation、`CADisplayLink`
和自定义测试运行器，不引入第三方依赖，不重构无关页面。

## 已确认的产品规则

- 同时支持手动分组和自动按分支生成分组建议。
- 自动分组只生成建议，用户确认后才创建 Group。
- 自动分组只包含分支独有的连通提交区段，共享祖先保持普通节点。
- 自动创建的 Group 首次默认展开。
- 手动 Group、折叠状态、节点位置和连线样式按仓库保存在本地。
- HTML 预览禁用 JavaScript、网络请求和本地文件访问。
- 直角折线不做自动避障。
- `Command` 用于切换单个提交的选择状态。
- `Shift` 用于追加选择，不实现范围选择。
- 跨组边聚合键固定为 `groupId + externalNodeId + direction`。
- Group 只保存 `origin`，组内成员只保存相对坐标，避免位置存在两份真值。
- Group 成员变化时只重建受影响端口；聚合键未变化时复用既有
  `side` 和 `offset`。
- 文字测量必须使用扣除头像、标签、作者和哈希等元素后的真实可用矩形，并以卡片
  圆角区域裁剪。

## 总体架构

现有 `CommitGraphLayoutResult` 继续表示 Git 拓扑、初始节点位置和原始父子边。
新增独立的提交画布场景层，负责用户可编辑状态：

```swift
public enum CommitGraphPortSide: String, Codable, Sendable {
    case top
    case right
    case bottom
    case left
}

public struct PortAnchor: Codable, Equatable, Sendable {
    public let side: CommitGraphPortSide
    public let offset: Double
}

public enum CommitGraphLineStyle: String, Codable, Sendable {
    case curve
    case orthogonal
}

public enum CommitGraphGroupSource: String, Codable, Sendable {
    case manual
    case branchSuggestion
}

public struct CommitGraphGroup: Codable, Equatable, Identifiable, Sendable {
    public let id: UUID
    public var title: String
    public var memberHashes: Set<String>
    public var source: CommitGraphGroupSource
    public var origin: GraphPoint
    public var relativePositions: [String: GraphPoint]
    public var isCollapsed: Bool
}
```

`CommitGraphSceneState` 保存：

- schema 版本；
- 未分组节点的绝对坐标；
- Group 及其 `origin` 和成员相对坐标；
- 普通边端口；
- 折叠跨组边端口；
- 当前线型。

Git 拓扑与场景状态分别拥有单一真值。拖动只能更新场景坐标；不得重新执行
`CommitGraphLayout`，也不得重算 Git 拓扑、Group 成员、聚合键或全部端口。

## Group 坐标与成员管理

创建 Group 时：

1. 对选择的提交按原始 Git 边做无向连通性检查。
2. 不连通时拒绝创建，并返回断开成员供界面说明。
3. 拒绝已经属于其他 Group 的提交；一个提交最多属于一个 Group。
4. 使用成员外接矩形左上角减去固定内边距作为 Group `origin`。
5. 将成员绝对坐标转换为相对 `origin` 的坐标。
6. 为 Group 的当前跨组聚合键分配稳定端口。

展开 Group 时，边界矩形由成员相对坐标、节点尺寸、标题栏和内边距派生，不另存
绝对位置。拖动标题栏只修改 Group `origin`；拖动组内节点只修改该成员的相对坐标。

折叠 Group 时，固定尺寸的 Group 卡片以 `origin` 为定位基准；组内节点和组内边
从可见投影中移除。

编辑 Group 成员时重新执行连通性检查。只为新增或已经失效的边界关系增删端口；
仍具有相同聚合键的端口必须复用原有 `PortAnchor`。

## 自动分组建议

自动分组不直接修改场景：

1. 用户点击“自动分组”。
2. ViewModel 在后台读取剩余本地提交分页，完成当前仓库全部本地与远程分支拓扑；
   过程显示进度并可取消。
3. 根据分支装饰和可达关系识别每个分支独有的提交集合。
4. 只保留内部连通、成员数不少于两个且尚未属于现有 Group 的候选。
5. 共享祖先和同时归属多个分支的提交不进入任何自动候选。
6. 候选以名称、提交数量、最早和最新提交摘要展示。
7. 用户勾选并确认后才创建 Group；候选本身不持久化。

已确认的 Group 不因后续重新生成建议而自动修改。

## 选择与拖动交互

- 普通单击提交继续打开提交详情。
- `Command + 点击`切换单个提交是否入选。
- `Shift + 点击`仅追加当前提交，不实现线性或时间范围选择。
- 选择两个以上提交后，工具栏显示“创建分组”。
- 选择不连通时确认按钮不可用，并显示连接性原因。
- 展开 Group 的标题栏与折叠 Group 卡片均可拖动。
- 未分组提交和组内提交均可拖动。
- 双击空白区域继续执行适配全部内容。
- 画布空白拖动继续平移视口。

现有 `CommitGraphInteractionSurface` 使用 `CADisplayLink`。它将扩展为 macOS 原生
逐帧更新合并器，承担浏览器 `requestAnimationFrame` 的职责：

- pointer move 只写入待处理的最新拖动增量；
- 同一显示帧只向 ViewModel 提交一次变更；
- Group 拖动只标记该 Group 及其相邻边为脏；
- 节点拖动只标记该节点及其相邻边为脏；
- 不触发完整 Git 布局或完整场景重建。

持久化写入使用短延迟合并，拖动结束立即落盘，持续拖动期间不逐帧写盘。

## 端口模型

每个端点保存固定 `PortAnchor`：

```swift
public struct CommitGraphEdgePorts: Codable, Equatable, Sendable {
    public let source: PortAnchor
    public let target: PortAnchor
}
```

`offset` 在读取和创建时限制在 `0...1`。端点坐标只由当前矩形和端口决定：

- `top`：`(minX + width * offset, minY)`
- `right`：`(maxX, minY + height * offset)`
- `bottom`：`(minX + width * offset, maxY)`
- `left`：`(minX, minY + height * offset)`

普通 Git 边在首次场景创建时分配端口。Group 在用户确认创建时为当前边界关系分配
端口。节点移动、Group 移动、画布缩放、折叠切换和线型切换都不能改变已有端口。

## 折叠投影与跨组边聚合

原始 Git 边方向定义为提交 `child` 指向其 `parent`：

- `leavingGroup`：`child` 在 Group 内，`parent` 是外部节点。
- `enteringGroup`：`child` 是外部节点，`parent` 在 Group 内。

折叠状态下：

- 组内节点不可见；
- 两端都在同一 Group 的边不可见；
- Group 与外部节点之间的边按以下键聚合：

```swift
public struct CollapsedEdgeKey: Hashable, Codable, Sendable {
    public let groupID: UUID
    public let externalNodeID: String
    public let direction: CommitGraphBoundaryDirection
}
```

同一键只生成一条可见边，保留原始边 ID 集合和 `count`。当 `count > 1` 时在线旁
显示 `×N`。相反方向使用不同键，不得错误合并。

投影时每条原始边只处理一次。若边的一端是折叠 Group、另一端是普通提交，
`externalNodeID` 使用普通提交哈希。若两端都是折叠 Group，由原始 `child` 所在
Group 作为键中的 `groupID`，`externalNodeID` 使用 `group:<目标 Group UUID>`，
方向为 `leavingGroup`，因此不会从目标 Group 再生成第二条重复边。

Group 展开时显示成员节点、组内边和原始跨组边，Group 边界只提供视觉归属和拖动
入口，不替代原始节点。

## 动态路径

### 曲线

曲线使用三次贝塞尔路径。起点和终点先由固定端口换算为绝对坐标。控制点分别沿两端
端口向外方向伸出，长度为：

```swift
max(56, min(distance * 0.35, 180))
```

切换线型只调用路径生成纯函数，端口不变。

### 直角折线

1. 起点和终点分别沿自身端口向外方向伸出 28px，得到两个 stub 点。
2. 起点端口为左/右时使用垂直中线，即两个 stub 的 `x` 中值。
3. 起点端口为上/下时使用水平中线，即两个 stub 的 `y` 中值。
4. 混合方向仍按起点端口方向选择中线。
5. 依次连接端点、stub、中线转折点、另一端 stub 和终点。
6. 删除距离小于容差的重复点。
7. 删除连续三点共线的中间点。
8. 不进行自动避障。

聚合标签的位置使用实际路径中点：折线按累计长度取中点，曲线使用 `t = 0.5`。

## 画布文字边界

现有按字符数截断无法正确处理中文宽字符和不同缩放比例，改为真实字体测量：

1. 为标题、作者、短哈希和分支标签分别计算布局矩形。
2. 标题可用矩形必须扣除头像、卡片内边距和右侧操作区域。
3. 元数据可用矩形必须扣除作者、哈希和分支标签的固定间隔。
4. 使用 `GraphicsContext.ResolvedText.measure(in:)`测量候选文本。
5. 超宽文本用二分搜索找到可容纳的最长前缀并追加省略号。
6. 最终绘制上下文以卡片圆角路径裁剪，确保任何缩放下都不越界。

## 文件预览分类

Core 新增不依赖 AppKit 的 `FilePreviewDescriptor` 和分类策略。分类同时参考路径扩展名、
内容签名、`GitFileContent.kind` 和实际字节数。

预览类型：

- `source`：普通 UTF-8 文本、Markdown 和常见脚本。
- `html`：HTML 文本，可在安全预览和源码之间切换。
- `rasterImage`：macOS 原生图片解码。
- `vectorImage`：SVG。
- `pdf`：PDF。
- `unsupportedBinary`：无法识别的二进制。
- `invalidText`：无法解码的非预览文本。
- `tooLarge`：超过对应类型上限。

大小限制：

- 文本、脚本、Markdown、HTML：2 MB。
- 图片、SVG、PDF：25 MB。

文件树已知大小超过对应扩展名策略时不读取 blob。读取后再次按内容签名、实际类型和
字节数校验，防止伪造扩展名绕过限制。

## 文件预览界面

### 源码与 Markdown

源码视图使用外层 `GeometryReader`取得右侧真实可用宽度。行号、分隔线和正文的
内容容器设置最小宽度为视口宽度减去内边距，并固定 `.topLeading` 对齐：

- 短内容始终靠左；
- 长内容继续支持横向和纵向滚动；
- Markdown 保持源码模式，不自动渲染。

语言识别覆盖 Swift、Objective-C、C/C++、Java、Kotlin、JavaScript、TypeScript、
Python、Ruby、Go、Rust、Shell、PowerShell、PHP、Lua、Dart、SQL、JSON、YAML、
TOML、XML 和 CSS。高亮保持轻量、只读，不引入编辑器或第三方解析器。

### 图片

- PNG、JPEG、GIF、TIFF、BMP、HEIC 及系统 ImageIO 支持的 WebP 由 `NSImage`
  直接读取内存数据。
- SVG 使用禁用脚本和网络的矢量视图。
- 默认等比适配，支持用户缩放和恢复适配。

### PDF

使用 `PDFKit.PDFView` 和 `PDFDocument(data:)`直接读取内存数据，提供系统原生的
翻页、缩放和搜索能力，不写临时文件。

### HTML

HTML 默认显示安全渲染预览，并提供“预览/源码”切换：

- `WKWebsiteDataStore.nonPersistent()`；
- 禁用 JavaScript；
- 内容规则阻止全部网络子资源；
- 内容安全策略仅允许内联样式、`data:`图片和`data:`字体；
- 拒绝 HTTP、HTTPS、文件 URL 和自定义协议导航；
- 不设置本地文件基址；
- 解码失败时仍可切换到源码查看。

## 状态隔离与错误处理

- 快速切换文件继续使用现有 request ID 和任务取消机制，旧结果不能覆盖新选择。
- 图片、PDF 或 HTML 解码失败时显示稳定错误状态。
- 场景文件损坏、版本不兼容或成员提交暂时未加载时不得影响 Git 数据读取。
- 场景恢复失败时回退自动布局并显示非阻塞提示。
- 分页后重新出现的提交复用已有持久化位置。
- 自动分组读取剩余提交时允许取消，取消不创建建议或 Group。
- 任何预览错误都不得执行文件内容、脚本或外部导航。

## 持久化

新增 `CommitGraphSceneStoring` 协议和 JSON 实现。文件位于 Application Support 下的
GitMate 专用目录，按仓库稳定 ID 分开保存。写入采用临时文件加原子替换。

保存内容只包括场景布局元数据，不包含访问令牌、仓库文件内容或提交差异。schema
版本不匹配时保留原文件供后续迁移，本次会话使用默认场景。

最终运行完整测试、Debug 构建、Release 构建、应用包签名和完整性校验。

## 非目标

- 不加入代码编辑、提交、暂存或推送能力。
- 不实现 HTML JavaScript 或远程资源执行。
- 不实现直角折线自动避障。
- 不实现 Shift 范围选择。
- 不让同一提交同时属于多个 Group。
- 不自动接受或持久化自动分组候选。
- 不改变现有 Git 提交读取顺序和全部本地、远程分支语义。
