# GitMate 本地优先仓库与封面懒加载设计

## 背景

GitMate 的主要定位是管理 Mac 上已有或明确选择同步的 GitHub 仓库，而不是持续镜像账户下的全部云端仓库。

当前页面 10–11 存在四类问题：

1. 工作区把账户下全部云端仓库都作为本地仓库检查，导致未选择同步的仓库也被统计为“本地副本缺失或损坏”。
2. 工作区会逐仓库请求在线摘要和 README。账户包含大量仓库时会快速消耗 GitHub API 配额，出现“GitHub API 已达到速率限制”。
3. 工作台内容背景没有稳定撑满窗口底部，仓库筛选器沿用了 macOS 原生菜单选择器的嵌套灰色选中效果。
4. 仓库墙会在数据流结束后一次解析并加载全部远程封面；超宽 README 图片还可能参与视图固有尺寸计算，撑开卡片和网格。

## 目标

- 工作台和默认仓库页只管理本地仓库。
- 云端仓库进入独立分页，只在用户主动浏览时加载。
- 云端未同步仓库不计入本地健康度、异常数量和今日焦点。
- 封面按视口加载，并提前预加载下一行。
- 下载成功的封面持久保存在本地，正常浏览不重复联网。
- 修复页面底部背景、筛选选中态和封面越界。
- 降低 GitHub API 请求量，并在限流后立即停止后续在线请求。

## 非目标

- 不在本次优化中增加组织管理、项目管理或批量删除功能。
- 不后台镜像账户下全部云端仓库。
- 不自动刷新全部云端仓库或全部封面。
- 不改变文件、提交、README 和提交图页面的主要信息架构。

## 产品原则

### 本地管理仓库

满足以下任一条件的仓库属于“本地仓库”：

- 本地仓库目录存在，状态为可用或损坏。
- 用户已选择手动同步或自动同步，即使本地副本随后意外缺失。

本地存在但同步方式为“不同步”的仓库仍属于本地仓库，GitMate继续提供只读浏览和本地状态管理，只是不主动同步。

### 云端仓库

同时满足以下条件的仓库属于“云端仓库”：

- GitHub 账户下存在。
- 本地没有仓库副本。
- 同步方式为“不同步”或尚未选择同步。

云端仓库不计入工作台的仓库健康度、同步异常、待关注数量和今日焦点。

### 同步偏好持久化

同步偏好按账户和仓库持久保存。应用重启后必须恢复真实选择，不能把缓存中的全部仓库默认恢复为手动同步。

如果仓库已从云端列表消失，但本地副本仍存在，继续在本地仓库页保留，并标记远端状态不可用。

## 信息架构

### 页面 10：全局工作台

工作台只汇总本地管理仓库：

- 仓库健康度只统计本地管理仓库。
- 本地缺失告警只针对已选择手动或自动同步的仓库。
- 本地改动、提交活动和 Git 状态直接从本地读取。
- 在线 Issue、Pull Request 和 Actions 摘要只为本地管理仓库刷新。
- 未选择同步的云端仓库不产生告警。

工作台内容区和侧边栏背景必须从窗口顶部连续铺满到底部，窗口缩放和内容不足一屏时也不能出现灰色断层。

### 页面 11：本地仓库与云端仓库

页面顶部增加一级切换：

- `本地仓库`：默认选中，显示本地管理仓库的电影海报墙。
- `云端仓库`：显示账户下尚未添加到本地的仓库。

本地仓库页保留搜索、可见性、语言、同步状态和排序。

云端仓库页提供：

- 搜索和可见性筛选。
- “下载到本地”操作。
- 同步方式选择：手动同步或自动同步。
- 手动“刷新云端仓库”按钮。
- 每页 30 个仓库，滚动到底部后加载下一页。

云端仓库下载成功后从云端分页移入本地仓库页，并复用已经保存的封面。

## 筛选控件视觉

仓库筛选器不再直接使用带系统内层底色的菜单 Picker，改为统一的自定义菜单胶囊：

- 默认状态：白色背景、深色文字、浅灰边框。
- 非默认筛选状态：浅蓝背景、蓝色文字、蓝色边框。
- 菜单箭头与文字使用同一颜色。
- 控件高度、圆角和内边距统一。
- 焦点、悬停和键盘操作保留清晰反馈。

排序控件与筛选控件使用同一视觉语言，搜索框不改变。

## 封面布局约束

- 仓库卡片宽度由网格列决定，封面不能参与列宽计算。
- 封面区域固定为 `2:3` 比例。
- README 图片使用填充裁切，不按图片原始宽高撑开布局。
- 卡片、封面和图片三层都执行边界裁切。
- 仓库名称、所有者和元数据必须限制行数，不能扩大卡片宽度。
- 图片解析失败或尺寸无效时继续使用稳定生成封面。

## 视口懒加载与预加载

封面加载范围为：

- 当前窗口内可见的仓库卡片。
- 当前滚动方向的下一行卡片，通常为 4–6 张。

其余卡片不请求 README 和图片。

加载规则：

- 同时最多执行 3 个封面请求。
- 当前可见卡片优先级高于预加载卡片。
- 快速滚动后，距离视口较远且尚未开始的任务从队列移除。
- 已经开始的请求只有在没有其他可见消费者时才取消。
- 切换到本地/云端另一分页或关闭窗口时取消该页面不再需要的任务。
- 加载失败后保留生成封面，不显示永久转圈。

## 封面持久缓存

封面下载成功后写入本地磁盘，同时记录：

- 账户 ID。
- 仓库 ID。
- 图片来源 URL。
- 本地文件位置。
- 内容哈希。
- 下载时间。
- `ETag` 和 `Last-Modified`，服务器提供时保存。
- 缓存版本和完整性状态。

正常启动、切换页面和滚动时：

- 优先读取磁盘缓存。
- 缓存存在且完整时不请求 README，也不重新下载图片。
- 离线时继续显示已经保存的封面。

缓存损坏时只清理目标仓库的损坏记录，并在卡片进入视口后重新获取。

## 手动刷新云端仓库

“刷新云端仓库”执行以下操作：

1. 重新获取云端仓库分页和基础元数据。
2. 将相关封面标记为“需要检查”，但不立即删除旧封面。
3. 当前可见卡片和下一行进入懒加载队列后再检查封面。
4. 有 `ETag` 或 `Last-Modified` 时使用条件请求。
5. 服务端返回 `304` 时继续使用本地文件。
6. 图片发生变化时原子替换缓存。
7. 刷新失败时继续显示旧封面。

刷新不会一次请求或删除全部仓库封面。

## GitHub API 请求策略

### 本地仓库页

- 首屏只读取本地目录、Git 状态和有效缓存。
- 在线摘要只针对本地管理仓库。
- 15 分钟内的有效在线摘要直接复用。
- README 只在单仓库 README 页面或封面进入视口且没有缓存时请求。

### 云端仓库页

- 用户进入分页后才请求云端仓库列表。
- 每页 30 个仓库。
- 列表使用仓库接口已有的名称、大小、可见性和更新时间，不为每张卡片额外请求 Issue、Pull Request 或 Actions 摘要。
- 封面遵循视口与下一行规则。

### 限流处理

收到 GitHub 限流响应后：

- 立即停止在线摘要、README 和封面队列继续发起新请求。
- 保留本地数据、有效缓存和生成封面。
- 限流状态记录到恢复时间。
- 页面提示改为“GitHub 在线信息暂停，预计某时间后可刷新；本地仓库功能不受影响”。
- 到达恢复时间后不自动批量重试，由用户点击刷新。

## 状态与组件边界

### 本地仓库目录

负责扫描本地目录并生成本地仓库集合，不依赖 GitHub API。

### 云端仓库分页加载器

负责按需获取账户仓库分页、排除已经属于本地集合的仓库，并维护刷新状态。

### 同步偏好存储

负责按账户保存和恢复仓库同步方式，不与工作区在线摘要缓存混用。

### 封面调度器

负责可见集合、预加载集合、优先级、最大并发数、取消和限流暂停。

### 封面缓存

负责磁盘文件、元数据、条件请求字段、原子替换和单仓库清理。

### 页面 ViewModel

只消费上述组件的稳定状态，不直接遍历全部仓库发起网络请求。

## 异常与降级

- 本地仓库扫描失败：只在对应仓库显示本地错误，不影响其他仓库。
- 云端列表加载失败：本地仓库页继续可用，云端分页显示重试入口。
- 封面加载失败：显示生成封面。
- 缓存读取失败：清理目标缓存记录，不能清空其他仓库封面。
- 限流：暂停新请求并显示恢复时间。
- 离线：停止在线请求，继续显示本地数据和磁盘封面。
- 取消：不得把取消状态显示为加载失败。

## 测试设计

### 数据边界

- 100 个云端未同步仓库不会产生 100 个本地缺失告警。
- 云端仓库不计入工作台健康度。
- 已选择同步但本地缺失的仓库仍显示需要重新同步。
- 本地存在但设置为不同步的仓库仍出现在本地仓库页。
- 重启后恢复真实同步偏好，不把全部仓库改为手动同步。

### 请求控制

- 本地工作台不会为云端未同步仓库请求在线摘要或 README。
- 云端分页每次最多加载 30 个仓库。
- 限流后不再启动新的在线请求。
- 切换分页和取消任务不会污染页面状态。

### 封面

- 只请求当前可见卡片和下一行卡片。
- 同时封面请求不超过 3 个。
- 可见卡片优先于预加载卡片。
- 已缓存封面正常浏览时不产生网络请求。
- 手动刷新后只检查进入加载范围的封面。
- `304` 响应继续复用本地文件。
- 刷新失败保留旧封面。
- 超宽、超高和损坏图片都不能撑开网格。

### 视觉与可访问性

- 页面背景在最小窗口和更高窗口中铺满底部。
- 筛选菜单默认状态和激活状态视觉清晰。
- 封面卡片保持 `2:3` 比例并限制宽度。
- 本地/云端分页、筛选器、刷新按钮和下载按钮拥有稳定的可访问标识。

## 验收标准

- 工作台不再显示未选择同步的云端仓库为本地异常。
- 进入工作区不会因为账户拥有大量云端仓库而立即消耗大量 GitHub API 请求。
- 本地仓库页默认打开并可离线使用。
- 云端仓库按 30 个一页加载。
- 当前窗口和下一行封面逐步出现，更远仓库不产生封面请求。
- 已加载封面重启后直接从本地显示。
- 手动刷新云端仓库不会一次刷新全部封面。
- 任意 README 图片都不能造成卡片或页面越界。
- 页面底部背景和筛选选中态符合确认后的白色主色调与高对比规范。
