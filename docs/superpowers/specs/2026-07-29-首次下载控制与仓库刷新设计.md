# GitMate 首次下载控制与仓库刷新设计

## 目标

优化登录后的仓库首次下载流程，使用户可以明确选择要下载的仓库、查看两个层级的进度，并在下载过程中立即暂停、继续或停止任务。同时允许用户手动刷新 GitHub 云端仓库列表。

## 功能范围

本次开发包含：

- 删除“自动同步”“不同步”“手动”三个同步方式选项。
- 仓库列表改为复选框多选，默认全部不选。
- 用户勾选哪些仓库，就首次 `clone` 哪些仓库。
- 主按钮文字改为“开始首次下载（Clone）”。
- 下载页面增加“暂停下载”，暂停后同一按钮改为“继续下载”。
- 暂停时立即挂起当前 Git 进程，继续时从原进程恢复。
- 保留“停止下载”，停止后终止当前 Git 进程并返回仓库选择页。
- 下载页面显示仓库总进度和当前仓库进度两个长条进度条。
- 仓库列表右上角增加“刷新云端仓库”按钮。

本次不开发：

- 自动同步。
- 定时拉取或后台持续更新。
- 手动上传（Push）。
- 手动下载更新（Pull）。
- 已下载仓库的同步方式设置。

## 仓库选择页面

仓库列表每行左侧显示复选框，仓库名称、头像、可见性、默认分支和大小保持不变。页面加载后默认不选择任何仓库。

列表标题栏右上角显示“刷新云端仓库”按钮。刷新时按钮显示加载状态并暂时禁用，调用当前账户对应的 GitHub API 重新读取仓库：

- 已存在仓库保留勾选状态。
- 新出现仓库默认不勾选。
- 云端已删除或账户失去访问权限的仓库从列表移除。
- 刷新失败时保留现有列表，并在页面内显示错误原因。

未选择仓库时，“开始首次下载（Clone）”按钮禁用。用户选择仓库后，还必须选择本机存储目录才能开始。

## 首次下载行为

用户点击“开始首次下载（Clone）”后，只处理已勾选仓库。每个仓库下载到用户所选父目录下的同名子文件夹。

下载前继续执行现有冲突检查：

- 同名普通文件会阻止下载。
- 包含普通内容的同名非 Git 文件夹会阻止下载。
- 指向其他远程地址的同名 Git 仓库会阻止下载。
- 已经是同一远程仓库的目录不重新 `clone`，本次首次下载将其视为已存在并跳过，避免隐式执行 Pull 或 Fetch。

这样可以保证“首次下载”只负责 Clone，不会混入后续同步行为。

## 暂停、继续与停止

同步控制器持有当前 Git 子进程：

- 点击“暂停下载”后立即挂起当前 Git 进程，文件保持原状，界面显示“已暂停”。
- 点击“继续下载”后恢复同一个 Git 进程，不重新开始当前仓库。
- 暂停期间不进入下一个仓库，两个进度条保持当前位置。
- 点击“停止下载”后终止当前 Git 进程，保留已经完整下载的仓库和当前目录中的 Git 临时数据，然后返回仓库选择页。
- 应用退出时终止仍在运行或暂停的子进程，避免遗留后台 Git 任务。

## 双进度条

第一个进度条为“仓库下载进度”：

- 显示 `已完成仓库数 / 已选择仓库数`。
- 只在一个仓库完整完成后增加。

第二个进度条为“当前仓库进度”：

- 解析 Git 标准错误输出中的百分比，例如 Receiving objects、Resolving deltas 和 Updating files。
- 显示当前阶段、百分比和最近活动文本。
- 新仓库开始时归零。
- Git 暂时没有提供百分比时显示不确定进度状态，不伪造百分比。
- 当前仓库完成时显示 100%。

## 状态与错误处理

- 暂停或继续失败时保持当前页面，并显示可读错误。
- Git 进程异常退出时沿用现有同步错误页面。
- 网络中断和授权失效继续进入现有专用页面。
- 刷新仓库与下载任务互斥：下载开始后仓库刷新按钮不可见，避免运行中改变队列。
- 所有 UI 更新均回到主线程；Git 输出解析和文件操作保持在后台执行。

## 测试范围

- 仓库默认全部未选择。
- 勾选状态转换为正确的首次下载队列。
- 刷新后保留已有仓库的勾选状态，新仓库默认未选，已删除仓库被移除。
- 暂停调用当前命令的挂起能力，继续调用恢复能力。
- 暂停时不推进仓库进度，恢复后任务可以完成。
- Git 百分比文本正确转换为当前仓库进度。
- 仓库总进度与当前仓库进度互不覆盖。
- 已存在同一远程仓库时不会隐式执行 Fetch。
- 停止后终止进程并回到仓库选择页。
- 大量仓库仍使用惰性列表，不因刷新或进度更新阻塞滚动。
