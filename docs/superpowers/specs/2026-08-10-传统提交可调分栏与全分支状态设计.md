# 传统提交可调分栏与全分支状态设计

## 背景与纠正

上一轮把“整体左右移动”理解成提交内容整体横向平移。用户实际需要的是拖动传统提交视图中间的竖向分割线，以调整左侧分支图与右侧提交信息的布局宽度。

当前实现还有两项限制：

1. `CommitGraphTraditionalBranchProjector` 按窗口宽度只选择 4–8 条分支，其余本地和远程分支合并到“其他分支”槽，无法同时看到全部分支身份。
2. 传统分支图没有区分远程已经存在的提交与只存在于本地、尚未推送的提交。

本设计替代上一份设计中的“提交内容整体横向拖动”交互，但保留已经实现的头像解析、首字母回退、真实可见行过滤和固定头部裁剪。

## 已确认术语

“本地未提交”在本需求中专指：

- 已经执行 Git commit；
- 可以从某个本地分支引用到达；
- 无法从任何本地保存的远程跟踪分支引用到达；
- 因而尚未推送到远端的本地提交。

工作区内尚未 commit 的暂存、修改和未跟踪文件不进入分支图，继续只显示在现有“工作区变更”摘要中。

## 目标

- 中间竖向分割线可用鼠标左右拖动，实时调整两侧宽度。
- 分割线位置按仓库持久化，重新打开软件后继续保持。
- `main` 是默认最左侧逻辑泳道；没有本地 `main` 时使用 `origin/main`，两者都不存在时回退仓库默认分支或当前 HEAD。
- 所有本地分支、远程分支和仅远程分支都进入传统提交图，不再折叠为“其他分支”。
- 本地分支与对应远程跟踪分支合并为一条逻辑泳道，避免共同历史重复绘制。
- 远程已知提交和连线使用实线；本地尚未推送提交和连线使用同色虚线。
- 分支很多时仍保持可读和流畅，不要求把所有泳道压缩进一个固定宽度。

## 非目标

- 不把尚未 commit 的工作区修改伪装成 Git 提交节点。
- 不发起新的 GitHub API 请求。
- 不主动执行 `git fetch`；远程状态以最近一次同步或刷新后保存在本地的 `refs/remotes/*` 为准。
- 不复制共同历史节点，不为本地与远程引用各画一份相同提交。
- 不改变画布式提交图的分组、区域、端口或布局行为。

## 方案选择

采用“全量逻辑分支 + 可调分栏 + 左侧内部横向视口”方案：

1. 本地分支与名称对应的远程分支组成一条逻辑分支；远程名称仍作为标签保留。
2. 所有逻辑分支均获得稳定泳道身份，不再受 4–8 条容量限制。
3. 左侧分支图宽度由可拖动分割线决定；泳道总宽度超过左侧区域时，只有左侧分支图内部横向滚动。
4. 右侧头像、提交标题、作者、时间、哈希和标签区域不参与横向滚动。

不采用“本地和远程各占一条泳道”，因为共同历史会重复并在分支较多时产生大量无意义平行线。也不保留当前隐藏分支聚合槽，因为它不满足所有分支可见要求。

## 逻辑分支合并

新增纯逻辑分支投影，输入为完整分支目录和完整引用指纹，输出稳定的逻辑分支列表。

配对规则：

1. 本地 `refs/heads/<name>` 优先与 `refs/remotes/origin/<name>` 配对。
2. 没有 `origin` 时，与其他远程中完整后缀 `<name>` 相同的分支配对；多个候选按远程名稳定排序，全部远程标签仍附着在同一逻辑分支上。
3. 没有远程对应项的本地分支单独保留。
4. 没有本地对应项的远程分支单独保留。
5. Detached HEAD 与无引用提交继续使用现有独立身份，不吞并真实分支。

逻辑分支包含：

- 稳定 `id`；
- 本地分支 ID（可空）；
- 一个或多个远程分支 ID；
- 展示名称与全部引用标签；
- tip 哈希集合；
- 最近活动时间；
- 稳定颜色编号；
- 稳定泳道编号。

共同历史提交仍只绘制一次。多个分支引用指向同一提交时，在该节点右侧展示全部本地/远程标签，并在空间不足时显示 `+N`，搜索浮层仍能找到每一个完整分支名。

## 泳道顺序

初始顺序固定为：

1. `main` 逻辑分支；
2. 当前 HEAD 所在逻辑分支（若不是 `main`）；
3. 其他本地逻辑分支；
4. 仅远程逻辑分支；
5. Detached 或 synthetic 身份。

同组内按最近活动时间倒序，再以稳定 ID 排序。`main` 的识别顺序为本地 `main`、`origin/main`、其他远程的 `main`。仓库没有任何 `main` 时，使用仓库默认分支或 HEAD 作为第一条泳道，不虚构不存在的 `main`。

用户打开仓库或重新进入传统布局时，左侧分支区域横向位置从第零泳道开始，因此默认首先看到最左侧主分支。分支区域横向滚动是瞬态状态，不写入场景。

## 远程实线与本地未推送虚线

刷新完整提交快照时一次性构建两个集合：

- `remoteReachableHashes`：从所有 `refs/remotes/*` tip 沿全部父边可到达的提交。
- `localReachableHashes`：从所有 `refs/heads/*` tip 沿全部父边可到达的提交。

提交状态：

- 哈希位于 `remoteReachableHashes`：远程已知，节点轮廓和以该提交为子节点的连线使用实线。
- 哈希只位于 `localReachableHashes`：本地未推送，节点轮廓和以该提交为子节点的连线使用虚线，并显示“未推送”徽标。
- 仅远程分支可达的提交：仍属于远程已知，使用实线。
- 没有远程引用：所有本地可达提交均视为本地未推送。

Merge 提交按子提交状态决定从该提交发出的全部父边线型，保持一个提交节点周围的视觉语义一致。浅克隆边界继续使用现有边界样式，不被误判为本地未推送提交。

该判断反映本地最近一次 fetch 后的远程跟踪状态，不声称实时代表服务器未抓取的新状态。

## 可拖动分割线

传统内容区分成三层：

1. 左侧分支图裁剪视口；
2. 中间 1 点可见分割线和 10 点透明拖动命中区；
3. 右侧固定提交信息区。

拖动规则：

- 鼠标悬停分割线时显示左右调整光标。
- 鼠标按下并拖动时只更新分栏宽度，不选择提交节点。
- 左侧最小宽度为 `min(220, viewportWidth * 0.45)`。
- 右侧目标最小宽度为 `min(420, viewportWidth * 0.55)`。
- 最大左侧宽度为 `max(minimumLeft, viewportWidth - minimumRight)`。
- 异常、非有限或越界值使用纯函数夹紧。
- 双击分割线恢复默认宽度。

默认宽度为 `clamp(viewportWidth * 0.38, 280...420)`，再按当前窗口边界夹紧。拖动时用本地呈现状态实时更新；鼠标松开时才把最终宽度写入场景，避免每个 pointermove 都触发磁盘保存。

分割线移动后：

- 左侧 Canvas、分支线和节点使用新的裁剪宽度；
- 右侧头像、提交文字和标签的起点统一移动到分割线右侧；
- 行背景、选中态和横向分隔线仍铺满整个提交内容区；
- 头像层继续只构建真实可见行并受内容区裁剪，不会穿透固定头部。

## 左侧分支内部横向滚动

所有逻辑泳道的内容总宽度为固定边距加 `泳道数量 × 泳道间距`。当总宽度超过左侧分栏宽度时：

- 触控板横向滚动只移动左侧分支图；
- 右侧头像和提交信息保持不动；
- 横向偏移夹紧，不露出空白；
- 只绘制当前左侧视口及小缓冲区相交的泳道、节点和连线；
- 主分支始终是第零泳道，初始偏移为零。

右侧提交区域不再整体横向平移。上一轮新增的整层横向偏移状态和鼠标拖动内容交互将移除，鼠标拖动只保留给中间分割线。

## 持久化与迁移

在 `CommitGraphSceneState` 中增加：

```swift
public var traditionalDividerWidth: Double?
```

场景 schema 递增一版。旧场景读取时该值为 `nil`，界面按默认公式计算；首次拖动结束后写入实际宽度。未来 schema 的只读保护、原子保存和按仓库隔离规则保持不变。

窗口变窄时只夹紧呈现宽度，不立即覆盖用户保存值；窗口恢复后优先恢复保存宽度。用户再次完成拖动时才更新保存值。

## 状态与数据流

1. 完整快照刷新读取所有本地和远程引用。
2. 后台派生阶段一次性计算逻辑分支、远程可达集合和每提交线型，不在 Canvas 绘制帧内遍历全历史。
3. ViewModel 原子安装派生结果，传统视图只消费不可变投影。
4. 分割线拖动只更新 SwiftUI 本地宽度；结束时通过 ViewModel 更新场景并触发一次持久化。
5. 左侧横向滚动只更新瞬态偏移，不重算 Git 拓扑、逻辑分支或可达集合。

## 大量分支性能

目标规模继续覆盖 50,000 个提交和至少 300 个本地/远程引用：

- 逻辑分支配对使用预构建名称索引，复杂度随引用数量线性增长。
- 远程/本地可达性使用一次父边遍历，不对每个分支重复 DFS。
- 每个提交的远程状态在派生阶段固化为 O(1) 查询。
- 垂直方向继续只绘制可见行和缓冲行。
- 水平方向增加可见泳道范围，只绘制左侧视口附近泳道。
- 分支标签使用预构建的哈希到标签索引，绘制行不扫描完整引用表。

## 错误与退化

- 仓库没有远程引用：本地提交全部用虚线，但页面仍可用。
- 仓库没有 `main`：回退默认分支或 HEAD，不创建假分支。
- 本地与远程同名但指向不同历史：仍属于同一逻辑分支，真实分叉和 Merge 由拓扑边表达。
- 多个远程包含同名分支：全部标签保留，`origin` 优先作为主要远程标签。
- 保存分割线失败：当前拖动结果在本次页面继续有效，并沿用现有非阻塞场景错误提示。
- 超窄窗口：按比例下调两侧最小值，不产生负宽度或越界。

## 测试策略

按用户要求，先一次性完成全部生产代码和测试用例编写，中途不执行分阶段测试；所有开发内容完成后再统一运行完整测试、Debug/Release 构建和打包校验。测试用例至少覆盖：

1. `main` 固定为第零逻辑泳道及无 `main` 的回退。
2. 本地分支与 `origin/<name>` 合并且全部标签保留。
3. 本地独有、远程独有和多远程同名分支全部进入投影。
4. 不再生成隐藏本地/远程聚合槽。
5. 远程可达提交为实线，本地独有提交为虚线。
6. Merge 的多条父边继承子提交线型。
7. 没有远程引用时全部本地提交为虚线。
8. 分割线默认值、左右边界、非有限输入和超窄窗口夹紧。
9. 场景新字段编码解码、旧 schema 迁移和未来 schema 保护。
10. 拖动期间不持久化，结束时只保存一次最终宽度。
11. 左侧横向偏移不移动右侧头像和提交信息。
12. 50,000 提交与 300 分支下的派生和局部绘制性能回归。

完成后运行完整核心测试两轮、Debug 构建、Release 构建、签名校验与 ZIP 完整性校验。

## 验收标准

- 可以直接拖动中间竖向分割线，实时改变分支图和提交信息宽度。
- 重新打开同一仓库后恢复最后一次完成拖动的位置。
- `main` 存在时默认显示在最左侧。
- 任意本地或远程分支都可在图或分支搜索中找到，不出现“其他分支”聚合代替真实分支。
- 远程已知提交使用实线，本地已 commit 但尚未 push 的提交使用虚线和“未推送”标识。
- 左侧分支很多时可以在左侧区域横向浏览，右侧头像和提交信息不移动。
- 工作区未 commit 修改继续只显示在工作区摘要，不生成伪提交。
- 头像不穿透固定头部，普通作者继续显示稳定首字母头像。
