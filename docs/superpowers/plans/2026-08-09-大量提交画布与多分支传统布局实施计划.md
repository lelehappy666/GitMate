# 大量提交画布与多分支传统布局 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在不改变 Git 拓扑、用户 Group、区域、端口和手动位置的前提下，为画布增加稳定的主干/分支束概览，并为传统视图增加四到八条自适应上下文泳道和可搜索的隐藏分支入口。

**架构：** `CommitGraphLaneTopology` 继续作为唯一完整拓扑；新增两个纯 Core 派生层：画布分支目录/分支束投影、传统上下文泳道投影。`CommitGraphViewModel` 在快照或场景语义变化时后台重建投影，SwiftUI 只消费不可变结果；平移、缩放、滚动和绘制不得遍历全部提交或 refs。

**技术栈：** Swift 6、SwiftUI、AppKit Canvas、Observation、Swift Package Manager、自定义 `GitMateCoreTestsRunner`。

## 全局约束

- macOS 最低版本保持 14，不增加第三方依赖。
- 画布最早提交在上、最新提交在下；传统布局最新提交在上、最早提交在下。
- 本地与远程 refs 可达的提交必须完整保留；聚合只改变显示投影。
- 工作区未提交变更保持独立本地状态，不伪装成提交。
- Group、折叠、版本区域、固定端口、线型和手动位置不得被刷新、自动布局或聚合破坏。
- 画布缩放阈值保持：完整 `>= 0.8`、紧凑 `>= 0.5 && < 0.8`、概览 `< 0.5`。
- 传统布局根据可用宽度显示四到八条泳道，分支再多也不能无限横向扩张。
- 所有文档和 Git 提交信息使用中文。
