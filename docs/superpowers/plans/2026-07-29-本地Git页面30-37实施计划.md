# GitMate 本地 Git 页面 30–37 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现页面 30–37 的真实本地 Git 工作流，包括大规模工作区变更、暂存与提交、Diff、Stash、历史改写、冲突解决、远程管理和 Fetch/Pull/Push。

**Architecture:** 使用 `/usr/bin/git`、强类型命令构建器和流式执行器。`GitMateCore` 负责 Git、凭据、串行写操作、解析和可测试页面状态；`GitMateApp` 只负责 SwiftUI 视图、路由和预览。所有测试写操作仅发生在临时仓库和本地 Bare Remote。

**Tech Stack:** Swift 6、SwiftUI、Observation、Foundation、Security、系统 `/usr/bin/git`、现有 `GitMateCoreTestsRunner`。

## Global Constraints

- 实际代码只在分支 `本地Git` 的隔离工作区开发，不在 `main` 上实现功能。
- 目标平台为 macOS 14 或更高版本。
- 开发范围严格限定为页面 30–37 和它们共用的本地 Git 基础设施。
- 不实现 Submodule、Git LFS、签名密钥管理、全局 Git 配置编辑、Reflog 恢复或页面 10–29。
- 固定使用 `/usr/bin/git`，不得通过 Shell 执行命令。
- 同一仓库同一时间只允许一个写操作，不同仓库可以并行。
- 普通暂存、取消暂存、提交、Stash Apply、创建 Stash 和 Fetch 直接执行；其他写操作按规格分级确认。
- 强制推送只允许 `--force-with-lease`，禁止裸 `--force`。
- HTTPS Token 只从钥匙串读取并放入子进程临时环境；SSH 只使用系统 SSH Agent。
- Token、认证头和私钥不得进入命令参数、日志、缓存、Journal 或远程地址。
- 提交签名遵循仓库或全局 Git 配置；签名失败不得降级为未签名提交。
- 工作区状态支持至少 50,000 个变更条目，批次最多 200 条，文件系统刷新防抖为 300ms。
- Diff 超过 2,097,152 字节或 20,000 行时默认显示摘要并分段加载。
- 主窗口默认尺寸 1180×760，最小尺寸 1040×680；外层不产生纵向页面滚动。
- 主色调为白色，正文使用高对比深色，用户身份使用真实头像。
- 所有文档与 Git 提交使用中文。
- 测试不得对用户真实仓库执行写操作，也不得依赖公网。
- 每个任务只精确暂存本任务文件，保留工作区内其他未提交改动。

实现规则：

- `ProcessGitCommandExecutor` 为每次调用创建独立 `Process`，不复用现有下载暂停状态。
- stdout 以原始 `Data` 流式返回，保留 NUL。
- stderr 按完整行缓冲后脱敏再返回。
- 非零退出只携带脱敏 stderr。
- `.terminateProcess` 在流取消时终止进程。
- `.finishToSafeState` 忽略 UI Task 取消并等待 Git 到达退出、冲突或失败状态。
- 标准输入写入后关闭 Pipe，提交说明和补丁不得进入参数。

- 所有环境都设置 `GIT_TERMINAL_PROMPT=0`。

- [ ] **Step 4: 实现 Coordinator 和 Journal**

```swift
public actor RepositoryOperationCoordinator {
    public func run<T: Sendable>(
        repositoryURL: URL,
        kind: GitOperationKind,
        operation: @Sendable () async throws -> T
    ) async throws -> T
}

public enum GitOperationKind: String, Codable, Equatable, Sendable {
    case stage
    case unstage
    case commit
    case stash
    case historyRewrite
    case conflictResolution
    case remoteConfiguration
    case fetch
    case pull
    case push
}

public struct RiskConfirmation: Equatable, Sendable {
    public let operationID: UUID
    public let repositoryID: String
    public let impactFingerprint: String
    public let createdAt: Date
}

public enum GitOperationResult: String, Codable, Equatable, Sendable {
    case running
    case succeeded
    case conflicted
    case failed
    case cancelled
}

public protocol GitOperationJournalRecording: Sendable {
    func record(_ entry: GitOperationJournalEntry) async throws
    func entries(repositoryID: String) async throws -> [GitOperationJournalEntry]
}

public struct GitOperationJournalEntry: Codable, Equatable, Sendable {
    public let repositoryID: String
    public let kind: GitOperationKind
    public let startedAt: Date
    public let finishedAt: Date?
    public let phase: String
    public let result: GitOperationResult
}
```

Journal 使用原子 JSON 写入，只接收已脱敏字段。文件固定写入 `~/Library/Application Support/GitMate/LocalGitJournal/<repository-id>.json`；`repository-id` 是规范化仓库路径 UTF-8 数据的 SHA-256 小写十六进制，使用 CryptoKit 计算，不把真实路径写入文件名。测试通过注入的临时目录验证原子替换，编码后的 JSON 不包含 `Authorization`、`Basic`、`ghp_`、`github_pat_` 或测试 Token。

每个写操作开始前通过只读 `git rev-parse --git-path index.lock` 定位锁；锁存在时返回 `.repositoryLocked`，同时读取 Merge/Rebase/Cherry-pick 状态给出恢复入口。任何服务都不得删除未知锁文件，也不得以重试覆盖正在运行的 Git 操作。

public enum GitHistoryOperationRequest: Equatable, Sendable {

    case rebase(onto: String)

    case conflicted

    case cherryPick
}

public struct GitRepositoryOperationState: Equatable, Sendable {

}

    func preflight(repositoryURL: URL, request: GitHistoryOperationRequest) async throws -> GitOperationPreflight
    func start(repositoryURL: URL, request: GitHistoryOperationRequest, confirmation: RiskConfirmation) async throws -> GitHistoryOperationResult
    func `continue`(repositoryURL: URL) async throws -> GitHistoryOperationResult
    func abort(repositoryURL: URL) async throws
    func state(repositoryURL: URL) async throws -> GitRepositoryOperationState
}

public enum GitOperationBlocker: Equatable, Sendable {
    case workingTreeNotClean
    case anotherOperationInProgress
    case invalidSource
    case conflictPredictionUnknown
}

public enum GitRecoveryAction: Equatable, Sendable {
    case createStash
    case resolveCurrentOperation
    case refresh
}

public enum GitConflictPrediction: Equatable, Sendable {
    case none
    case likely(paths: [String])
    case unknown
}

    public let affectedFiles: [String]

    public let confirmation: RiskConfirmation?
}

```swift
public protocol GitTransferServicing: Sendable {
    func planFetch(repositoryURL: URL, remote: String) async throws -> GitTransferPlan
    func fetch(repositoryURL: URL, remote: String, context: GitCredentialContext) -> AsyncThrowingStream<GitTransferEvent, Error>
    func planPull(repositoryURL: URL, remote: String, branch: String) async throws -> GitTransferPlan
    func pull(repositoryURL: URL, plan: GitTransferPlan, context: GitCredentialContext, confirmation: RiskConfirmation) -> AsyncThrowingStream<GitTransferEvent, Error>
    func planPush(repositoryURL: URL, remote: String, branch: String, mode: PushMode) async throws -> GitTransferPlan
    func push(repositoryURL: URL, plan: GitTransferPlan, context: GitCredentialContext, confirmation: RiskConfirmation) -> AsyncThrowingStream<GitTransferEvent, Error>
}

public enum PullStrategy: Equatable, Sendable {
    case fastForwardOnly
    case merge
    case rebase
}

public enum PushMode: Equatable, Sendable {
    case normal
    case forceWithLease
}

public enum GitTransferOperation: Equatable, Sendable {
    case fetch
    case pull
    case push
}

public struct GitTransferPlan: Equatable, Sendable {
    public let operation: GitTransferOperation
    public let remote: String
    public let branch: String?
    public let pullStrategy: PullStrategy?
    public let pushMode: PushMode?
    public let expectedRemoteOID: String?
    public let ahead: Int?
    public let behind: Int?
    public let estimatedBytes: Int64?
    public let confirmation: RiskConfirmation?

    public static func forcePush(
        remote: String,
        branch: String,
        expectedRemoteOID: String
    ) -> GitTransferPlan
}

public enum GitTransferPhase: Equatable, Sendable {
    case connecting
    case negotiating
    case transferring
    case integrating
    case conflicted
    case completed
}

public enum GitBranchProtectionStatus: Equatable, Sendable {
    case protected(summary: String)
    case unprotected
    case unverified
}

public protocol GitBranchProtectionChecking: Sendable {
    func status(remote: GitRemote, branch: String) async -> GitBranchProtectionStatus
}

public struct GitTransferEvent: Equatable, Sendable {
    public let phase: GitTransferPhase
    public let currentObjects: Int?
    public let totalObjects: Int?
    public let bytesPerSecond: Int64?
    public let message: String?
}

public struct PullStrategyResolver: Sendable {
    public init(executor: any GitCommandExecuting = ProcessGitCommandExecutor())
    public func resolve(repositoryURL: URL) async throws -> PullStrategy
}
```

实现规则：

- Fetch 与 Push 使用 `.terminateProcess`。
- Pull 拆成 Fetch 和本地整合；只允许在 Fetch 阶段取消。
- 本地整合使用解析出的 `.fastForwardOnly`、`.merge` 或 `.rebase`。
- 进入冲突后返回 `.conflicted` 并交给页面 35。
- 普通 Push 预检 non-fast-forward。
- 强制 Push 必须携带最新远程 OID 的 `--force-with-lease=<ref>:<oid>`。
- 多引用 Push 优先 `--atomic`；不支持时返回需要用户重新确认的能力提示。
- 数据量无法低成本估算时为 `nil`，页面显示“未知”。
- `PullStrategyResolver` 按仓库配置优先读取 `pull.ff` 和 `pull.rebase`：`pull.ff=only` 返回 `.fastForwardOnly`；否则 `pull.rebase=true|merges|interactive` 返回 `.rebase`；其余返回 `.merge`。解析失败返回脱敏错误，不猜测用户策略。
- `GitTransferService` 与 `GitRemoteService` 一样默认使用 `.production`，本地 Bare Remote 测试显式注入 `.localTest`。
- `GitTransferService` 可注入 `GitBranchProtectionChecking?`；只有已有 GitHub API 账户上下文时调用，缺失、无权限或非 GitHub 远程统一返回 `.unverified`，最终结果始终以远程 Git 响应为准。

public enum LocalGitRoute: CaseIterable, Equatable, Sendable {
    case workingTree
    case commit
    case diff
    case stash
    case historyOperation
    case conflicts
    case remotes
    case transfer

    public var pageNumber: Int {
        switch self {
        case .workingTree: return 30
        case .commit: return 31
        case .diff: return 32
        case .stash: return 33
        case .historyOperation: return 34
        case .conflicts: return 35
        case .remotes: return 36
        case .transfer: return 37
        }
    }

    public init?(pageNumber: Int) {
        guard let route = Self.allCases.first(where: { $0.pageNumber == pageNumber }) else {
            return nil
        }
        self = route
    }
}
